The harness should answer five questions:

1. **Correctness:** Does RedlineDB return the same results as SQLite for the supported SQL subset?
2. **Durability:** Does strict mode lose zero acknowledged commits?
3. **Single-thread speed:** Does RedlineDB match or beat SQLite on key OLTP paths?
4. **Concurrent speed:** Does RedlineDB clearly beat SQLite where SQLite’s single-writer model is the bottleneck?
5. **Memory discipline:** Does RedlineDB stay inside its configured memory budget?

SQLite WAL is the right baseline, but the benchmark must respect SQLite’s actual modes. SQLite WAL permits concurrent readers and a writer, but because there is one WAL file, SQLite allows only one writer at a time; that is the concurrency ceiling RedlineDB should attack. SQLite also has materially different durability behavior between `synchronous=FULL` and `synchronous=NORMAL`: in WAL mode, FULL adds a WAL sync after each transaction commit, while NORMAL avoids syncs during most transactions and can lose durability after power loss even though consistency is preserved. Those modes must never be mixed in one comparison. ([SQLite][1])

# Benchmarking rules

## Rule 1: never compare different durability modes

Define these modes explicitly:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub enum DurabilityMode {
    /// A commit may return only after the commit is durable across OS crash / power-loss assumptions.
    Strict,

    /// Commit can return after WAL append reaches the OS, with fsync deferred to checkpoint or periodic sync.
    Normal,

    /// Development / bulk-load / unsafe mode. No durability claims.
    DevUnsafe,
}
```

Map them like this:

```text
RedlineDB Strict     <-> SQLite WAL + synchronous=FULL
RedlineDB Normal     <-> SQLite WAL + synchronous=NORMAL
RedlineDB DevUnsafe  <-> SQLite WAL/OFF variant, clearly labeled unsafe
```

SQLite WAL defaults and checkpoint behavior also matter. SQLite’s WAL auto-checkpoint default is around 1000 pages, long readers can prevent checkpoints from completing, and unchecked WAL growth can hurt read performance. So the harness must explicitly configure checkpoint thresholds instead of inheriting accidental defaults. ([SQLite][1])

## Rule 2: compare API-level reality, not internal fantasies

For RedlineDB, benchmark the public embedded SQL API that users will call:

```rust
let mut conn = db.connect()?;
let mut stmt = conn.prepare("INSERT INTO kv(k, v) VALUES (?, ?)")?;
stmt.bind_i64(1, key)?;
stmt.bind_blob(2, value)?;
stmt.step()?;
```

For SQLite, do the equivalent with prepared statements.

Do **not** compare:

```text
RedlineDB internal heap_insert()
```

against:

```text
SQLite SQL INSERT
```

unless the report labels it as an internal kernel microbenchmark.

## Rule 3: include SQLite’s best reasonable baselines

For write-heavy concurrency, include at least three SQLite variants:

```text
sqlite-wal-full
sqlite-wal-normal
sqlite-wal-normal-queued-writer
```

The queued-writer variant is important because many real SQLite applications avoid `SQLITE_BUSY` by funneling writes through one writer thread. RedlineDB should beat raw concurrent SQLite and should still look good against the queued-writer baseline.

## Rule 4: measure bytes written, not just file size

File size deltas lie.

SQLite can reuse WAL space after checkpointing, so:

```text
wal_file_size_after - wal_file_size_before
```

does **not** equal WAL bytes written.

You need I/O byte accounting:

```text
wal_bytes_written
data_bytes_written
sync_count
sync_ns
checkpoint_write_bytes
checkpoint_sync_ns
```

For RedlineDB, expose this through internal stats. For SQLite, wrap the SQLite VFS with a Rust FFI metered VFS, or run a platform-specific I/O tracer. The VFS route is cleaner for repeatability.

# Hot-path benchmark design

## Avoid benchmark overhead

The hot loop should not:

```text
allocate
format strings
lock shared state
send per-op messages
parse SQL
create connections
open files
update global histograms
```

It should:

```text
use one connection/session per actor thread
use prepared statements
use preallocated payload buffers
record latency into thread-local histograms
accumulate counters locally
merge after the run
```

# SQLite baseline driver

For correctness tests, `rusqlite` is fine. For certification speed tests, use raw SQLite FFI so the harness does not benchmark wrapper overhead.

## SQLite configuration

For a new database:

```sql
PRAGMA page_size = 4096;
PRAGMA journal_mode = WAL;
PRAGMA synchronous = FULL;
PRAGMA wal_autocheckpoint = 1000;
PRAGMA cache_size = -262144; -- KiB if negative; 256 MiB here
PRAGMA temp_store = MEMORY;
PRAGMA busy_timeout = 5000;
```

For `NORMAL`:

```sql
PRAGMA synchronous = NORMAL;
```

For unsafe/dev:

```sql
PRAGMA synchronous = OFF;
```

Use `FULL` vs `NORMAL` exactly because SQLite’s own docs say WAL FULL adds an extra sync after each commit while NORMAL avoids syncs during most transactions. That difference can dominate write benchmarks. ([SQLite][2])

## Raw SQLite connection skeleton

```rust
use anyhow::{anyhow, bail, Result};
use libsqlite3_sys as ffi;
use std::ffi::{CStr, CString};
use std::os::raw::{c_char, c_int};
use std::path::Path;
use std::ptr;
use std::time::Duration;

pub struct RawSqliteEngine {
    path: std::path::PathBuf,
    cfg: DbConfig,
}

impl RawSqliteEngine {
    pub fn open(cfg: DbConfig) -> Result<Self> {
        if cfg.create_fresh {
            let _ = std::fs::remove_file(&cfg.path);
            let _ = std::fs::remove_file(cfg.path.with_extension("db-wal"));
            let _ = std::fs::remove_file(cfg.path.with_extension("db-shm"));
        }

        {
            let mut conn = RawSqliteConn::open_path(&cfg.path)?;
            conn.configure(&cfg)?;
            conn.execute_batch(
                r#"
                CREATE TABLE IF NOT EXISTS kv (
                    k INTEGER PRIMARY KEY,
                    v BLOB NOT NULL,
                    updated_at INTEGER NOT NULL
                );
                "#,
            )?;
        }

        Ok(Self { path: cfg.path.clone(), cfg })
    }
}

impl Engine for RawSqliteEngine {
    fn name(&self) -> &'static str {
        match self.cfg.durability {
            DurabilityMode::Strict => "sqlite-wal-full",
            DurabilityMode::Normal => "sqlite-wal-normal",
            DurabilityMode::DevUnsafe => "sqlite-wal-off",
        }
    }

    fn connect(&self) -> Result<Box<dyn Connection>> {
        let mut conn = RawSqliteConn::open_path(&self.path)?;
        conn.configure(&self.cfg)?;
        conn.prepare_hot_statements()?;
        Ok(Box::new(conn))
    }

    fn checkpoint(&self) -> Result<CheckpointStats> {
        let start = std::time::Instant::now();
        let mut conn = RawSqliteConn::open_path(&self.path)?;
        conn.execute_batch("PRAGMA wal_checkpoint(PASSIVE);")?;
        Ok(CheckpointStats {
            elapsed_ns: start.elapsed().as_nanos() as u64,
            pages_checkpointed: 0,
            wal_bytes_after: file_len(self.path.with_extension("db-wal")),
        })
    }

    fn stats(&self) -> Result<EngineStats> {
        // Best version uses a metered VFS. File length alone is insufficient.
        Ok(EngineStats::default())
    }

    fn file_sizes(&self) -> Result<FileSizeStats> {
        Ok(FileSizeStats {
            db_file_bytes: file_len(&self.path),
            wal_file_bytes: file_len(format!("{}-wal", self.path.display())),
            shm_file_bytes: file_len(format!("{}-shm", self.path.display())),
        })
    }
}

fn file_len<P: AsRef<Path>>(p: P) -> u64 {
    std::fs::metadata(p).map(|m| m.len()).unwrap_or(0)
}
```

## Raw SQLite connection

```rust
pub struct RawSqliteConn {
    db: *mut ffi::sqlite3,

    insert_kv: *mut ffi::sqlite3_stmt,
    read_kv: *mut ffi::sqlite3_stmt,
    update_kv: *mut ffi::sqlite3_stmt,
    delete_kv: *mut ffi::sqlite3_stmt,
    range_kv: *mut ffi::sqlite3_stmt,
}

unsafe impl Send for RawSqliteConn {}

impl RawSqliteConn {
    pub fn open_path(path: &Path) -> Result<Self> {
        let c_path = CString::new(path.to_string_lossy().as_bytes())?;
        let mut db: *mut ffi::sqlite3 = ptr::null_mut();

        let flags = ffi::SQLITE_OPEN_READWRITE
            | ffi::SQLITE_OPEN_CREATE
            | ffi::SQLITE_OPEN_NOMUTEX;

        let rc = unsafe {
            ffi::sqlite3_open_v2(
                c_path.as_ptr(),
                &mut db,
                flags,
                ptr::null(),
            )
        };

        if rc != ffi::SQLITE_OK {
            let msg = sqlite_errmsg(db);
            unsafe {
                if !db.is_null() {
                    ffi::sqlite3_close(db);
                }
            }
            bail!("sqlite open failed: {msg}");
        }

        Ok(Self {
            db,
            insert_kv: ptr::null_mut(),
            read_kv: ptr::null_mut(),
            update_kv: ptr::null_mut(),
            delete_kv: ptr::null_mut(),
            range_kv: ptr::null_mut(),
        })
    }

    pub fn configure(&mut self, cfg: &DbConfig) -> Result<()> {
        self.busy_timeout(Duration::from_millis(cfg.busy_timeout_ms))?;

        // page_size matters only before the DB is initialized.
        self.execute_batch(&format!("PRAGMA page_size = {};", cfg.page_size))?;
        self.execute_batch("PRAGMA journal_mode = WAL;")?;

        match cfg.durability {
            DurabilityMode::Strict => self.execute_batch("PRAGMA synchronous = FULL;")?,
            DurabilityMode::Normal => self.execute_batch("PRAGMA synchronous = NORMAL;")?,
            DurabilityMode::DevUnsafe => self.execute_batch("PRAGMA synchronous = OFF;")?,
        }

        self.execute_batch(&format!(
            "PRAGMA wal_autocheckpoint = {};",
            cfg.checkpoint_pages
        ))?;

        let cache_kib = (cfg.cache_bytes / 1024) as i64;
        self.execute_batch(&format!("PRAGMA cache_size = -{};", cache_kib))?;
        self.execute_batch("PRAGMA temp_store = MEMORY;")?;

        Ok(())
    }

    pub fn busy_timeout(&mut self, timeout: Duration) -> Result<()> {
        let ms = timeout.as_millis().min(i32::MAX as u128) as c_int;
        let rc = unsafe { ffi::sqlite3_busy_timeout(self.db, ms) };
        self.check(rc)
    }

    pub fn prepare_hot_statements(&mut self) -> Result<()> {
        self.insert_kv = self.prepare(
            "INSERT INTO kv(k, v, updated_at) VALUES (?1, ?2, ?3)"
        )?;

        self.read_kv = self.prepare(
            "SELECT v FROM kv WHERE k = ?1"
        )?;

        self.update_kv = self.prepare(
            "UPDATE kv SET v = ?2, updated_at = ?3 WHERE k = ?1"
        )?;

        self.delete_kv = self.prepare(
            "DELETE FROM kv WHERE k = ?1"
        )?;

        self.range_kv = self.prepare(
            "SELECT k, v FROM kv WHERE k >= ?1 ORDER BY k LIMIT ?2"
        )?;

        Ok(())
    }

    fn prepare(&mut self, sql: &str) -> Result<*mut ffi::sqlite3_stmt> {
        let c_sql = CString::new(sql)?;
        let mut stmt: *mut ffi::sqlite3_stmt = ptr::null_mut();

        let rc = unsafe {
            ffi::sqlite3_prepare_v3(
                self.db,
                c_sql.as_ptr(),
                -1,
                ffi::SQLITE_PREPARE_PERSISTENT as u32,
                &mut stmt,
                ptr::null_mut(),
            )
        };

        self.check(rc)?;
        Ok(stmt)
    }

    pub fn execute_batch(&mut self, sql: &str) -> Result<()> {
        let c_sql = CString::new(sql)?;
        let rc = unsafe {
            ffi::sqlite3_exec(
                self.db,
                c_sql.as_ptr(),
                None,
                ptr::null_mut(),
                ptr::null_mut(),
            )
        };
        self.check(rc)
    }

    #[inline]
    fn check(&self, rc: c_int) -> Result<()> {
        if rc == ffi::SQLITE_OK {
            Ok(())
        } else {
            Err(anyhow!("sqlite error {}: {}", rc, sqlite_errmsg(self.db)))
        }
    }
}

impl Connection for RawSqliteConn {
    fn execute_batch(&mut self, sql: &str) -> Result<()> {
        RawSqliteConn::execute_batch(self, sql)
    }

    fn begin(&mut self, mode: TxMode) -> Result<()> {
        match mode {
            TxMode::Deferred => self.execute_batch("BEGIN;"),
            TxMode::Immediate => self.execute_batch("BEGIN IMMEDIATE;"),
        }
    }

    fn commit(&mut self) -> Result<()> {
        self.execute_batch("COMMIT;")
    }

    fn rollback(&mut self) -> Result<()> {
        self.execute_batch("ROLLBACK;")
    }

    fn kv_insert(&mut self, k: i64, v: &[u8], updated_at: i64) -> Result<()> {
        unsafe {
            ffi::sqlite3_reset(self.insert_kv);
            ffi::sqlite3_clear_bindings(self.insert_kv);

            self.bind_i64(self.insert_kv, 1, k)?;
            self.bind_blob_static(self.insert_kv, 2, v)?;
            self.bind_i64(self.insert_kv, 3, updated_at)?;

            self.step_done(self.insert_kv)
        }
    }

    fn kv_read_hash(&mut self, k: i64) -> Result<Option<u64>> {
        unsafe {
            ffi::sqlite3_reset(self.read_kv);
            ffi::sqlite3_clear_bindings(self.read_kv);

            self.bind_i64(self.read_kv, 1, k)?;

            let rc = ffi::sqlite3_step(self.read_kv);
            if rc == ffi::SQLITE_ROW {
                let ptr = ffi::sqlite3_column_blob(self.read_kv, 0) as *const u8;
                let len = ffi::sqlite3_column_bytes(self.read_kv, 0) as usize;
                let bytes = std::slice::from_raw_parts(ptr, len);
                Ok(Some(fast_hash64(bytes)))
            } else if rc == ffi::SQLITE_DONE {
                Ok(None)
            } else {
                Err(anyhow!("sqlite read step failed: {}", sqlite_errmsg(self.db)))
            }
        }
    }

    fn kv_update(&mut self, k: i64, v: &[u8], updated_at: i64) -> Result<()> {
        unsafe {
            ffi::sqlite3_reset(self.update_kv);
            ffi::sqlite3_clear_bindings(self.update_kv);

            self.bind_i64(self.update_kv, 1, k)?;
            self.bind_blob_static(self.update_kv, 2, v)?;
            self.bind_i64(self.update_kv, 3, updated_at)?;

            self.step_done(self.update_kv)
        }
    }

    fn kv_delete(&mut self, k: i64) -> Result<()> {
        unsafe {
            ffi::sqlite3_reset(self.delete_kv);
            ffi::sqlite3_clear_bindings(self.delete_kv);

            self.bind_i64(self.delete_kv, 1, k)?;
            self.step_done(self.delete_kv)
        }
    }

    fn kv_range_scan_hash(&mut self, lo: i64, limit: i64) -> Result<u64> {
        unsafe {
            ffi::sqlite3_reset(self.range_kv);
            ffi::sqlite3_clear_bindings(self.range_kv);

            self.bind_i64(self.range_kv, 1, lo)?;
            self.bind_i64(self.range_kv, 2, limit)?;

            let mut h = 0_u64;

            loop {
                let rc = ffi::sqlite3_step(self.range_kv);

                if rc == ffi::SQLITE_ROW {
                    let k = ffi::sqlite3_column_int64(self.range_kv, 0);
                    let ptr = ffi::sqlite3_column_blob(self.range_kv, 1) as *const u8;
                    let len = ffi::sqlite3_column_bytes(self.range_kv, 1) as usize;
                    let bytes = std::slice::from_raw_parts(ptr, len);
                    h ^= fast_hash64_i64(k) ^ fast_hash64(bytes);
                } else if rc == ffi::SQLITE_DONE {
                    return Ok(h);
                } else {
                    return Err(anyhow!("sqlite range step failed: {}", sqlite_errmsg(self.db)));
                }
            }
        }
    }
}

impl RawSqliteConn {
    #[inline]
    unsafe fn bind_i64(
        &self,
        stmt: *mut ffi::sqlite3_stmt,
        idx: c_int,
        v: i64,
    ) -> Result<()> {
        let rc = ffi::sqlite3_bind_int64(stmt, idx, v);
        if rc == ffi::SQLITE_OK {
            Ok(())
        } else {
            Err(anyhow!("sqlite bind_i64 failed: {}", sqlite_errmsg(self.db)))
        }
    }

    #[inline]
    unsafe fn bind_blob_static(
        &self,
        stmt: *mut ffi::sqlite3_stmt,
        idx: c_int,
        bytes: &[u8],
    ) -> Result<()> {
        // SQLITE_STATIC is safe here because bytes live until sqlite3_step finishes.
        let rc = ffi::sqlite3_bind_blob64(
            stmt,
            idx,
            bytes.as_ptr() as *const _,
            bytes.len() as u64,
            ffi::SQLITE_STATIC(),
        );

        if rc == ffi::SQLITE_OK {
            Ok(())
        } else {
            Err(anyhow!("sqlite bind_blob failed: {}", sqlite_errmsg(self.db)))
        }
    }

    #[inline]
    unsafe fn step_done(&self, stmt: *mut ffi::sqlite3_stmt) -> Result<()> {
        let rc = ffi::sqlite3_step(stmt);
        if rc == ffi::SQLITE_DONE {
            Ok(())
        } else {
            Err(anyhow!("sqlite step failed: {}", sqlite_errmsg(self.db)))
        }
    }
}

impl Drop for RawSqliteConn {
    fn drop(&mut self) {
        unsafe {
            for stmt in [
                self.insert_kv,
                self.read_kv,
                self.update_kv,
                self.delete_kv,
                self.range_kv,
            ] {
                if !stmt.is_null() {
                    ffi::sqlite3_finalize(stmt);
                }
            }

            if !self.db.is_null() {
                ffi::sqlite3_close(self.db);
            }
        }
    }
}

fn sqlite_errmsg(db: *mut ffi::sqlite3) -> String {
    if db.is_null() {
        return "<null sqlite handle>".to_string();
    }

    unsafe {
        let ptr = ffi::sqlite3_errmsg(db);
        if ptr.is_null() {
            "<null sqlite errmsg>".to_string()
        } else {
            CStr::from_ptr(ptr as *const c_char)
                .to_string_lossy()
                .into_owned()
        }
    }
}
```

```rust
impl RedlineEngine {
    pub fn open(cfg: DbConfig) -> anyhow::Result<Self> {
        let mut builder = redlinedb::DatabaseOptions::new();

        builder
            .path(&cfg.path)
            .page_size(cfg.page_size)
            .buffer_pool_bytes(cfg.cache_bytes)

                builder.unsafe_no_fsync(true);

                "DELETE FROM kv WHERE k = ?1"

    }
```

The exact RedlineDB API names will differ, but the contract matters:

```text

one session per worker thread

stats are exact, not inferred
```

# Runner

## Run lifecycle

Every benchmark run should do this:

```text
1. Create fresh database directory
2. Open engine with explicit config
3. Create schema
4. Preload data if needed
5. Force checkpoint
6. Close/reopen database
7. Warm up without measuring
8. Reset stats
9. Start memory sampler
10. Start all actors with a barrier
11. Run fixed-time or fixed-op measurement
12. Stop actors
13. Merge per-thread histograms
14. Collect engine stats
15. Collect file sizes
16. Run integrity/correctness checks
17. Emit JSON report
18. Evaluate gates
```

## Runner code

```rust
use anyhow::Result;
use crossbeam_utils::thread;
use std::sync::{
    Arc,
    Barrier,
    atomic::{AtomicBool, Ordering},

use std::time::{Duration, Instant};

pub struct RunConfig {
    pub engine_name: String,
    pub workload_name: String,
    pub threads: usize,

pub fn run_benchmark(
    engine: Arc<dyn Engine>,
    workload: Arc<dyn Workload>,
    cfg: RunConfig,

    workload.setup(engine.as_ref(), &cfg)?;

        cfg.warmup,
        true,

    let before_stats = engine.stats()?;
    let before_files = engine.file_sizes()?;

    let worker_reports = run_phase(
        engine.clone(),
        workload.clone(),
        &cfg,
        cfg.measurement,

    let elapsed = start.elapsed();

    let memory = memory_sampler.stop()?;

    let after_stats = engine.stats()?;
    let after_files = engine.file_sizes()?;

    let correctness = workload.verify(engine.as_ref(), &cfg)?;

    let merged = merge_worker_metrics(worker_reports)?;

    let io = IoReport {

        wal_bytes_per_op: bytes_per_op(

        data_bytes_per_op: bytes_per_op(
            after_stats.data_bytes_written.saturating_sub(before_stats.data_bytes_written),

        ),
        wal_syncs: after_stats.wal_syncs.saturating_sub(before_stats.wal_syncs),
        data_syncs: after_stats.data_syncs.saturating_sub(before_stats.data_syncs),
        sync_p50_ns: None,
        sync_p99_ns: None,
        db_file_bytes: after_files.db_file_bytes,
        wal_file_bytes: after_files.wal_file_bytes,
    };

        op_p50_ns: merged.insert_hist.value_at_quantile(0.50),
        op_p95_ns: merged.insert_hist.value_at_quantile(0.95),

fn run_phase(
    engine: Arc<dyn Engine>,
    workload: Arc<dyn Workload>,
    cfg: &RunConfig,
    duration: Duration,
    warmup: bool,
) -> Result<Vec<WorkerMetrics>> {
    let stop = Arc::new(AtomicBool::new(false));
    let barrier = Arc::new(Barrier::new(cfg.threads + 1));

    let mut reports = Vec::with_capacity(cfg.threads);

    thread::scope(|scope| {
        let mut handles = Vec::new();

        for actor_id in 0..cfg.threads {
            let engine = engine.clone();
            let workload = workload.clone();
            let stop = stop.clone();
            let barrier = barrier.clone();

            let actor_count = cfg.threads;
            let seed = split_seed(cfg.seed, actor_id as u64);
            let payload_bytes = cfg.payload_bytes;

            handles.push(scope.spawn(move |_| -> Result<WorkerMetrics> {
                let mut conn = engine.connect()?;

                barrier.wait();

                let ctx = ActorCtx {
                    actor_id,
                    actor_count,
                    seed,
                    payload_bytes,
                    stop,
                    started_at: Instant::now(),
                    measurement: duration,
                };

                workload.run_actor(ctx, conn.as_mut())
            }));
        }

        barrier.wait();

        std::thread::sleep(duration);
        stop.store(true, Ordering::Release);

        for handle in handles {
            reports.push(handle.join().unwrap()?);
        }

        Ok::<_, anyhow::Error>(())
    })
    .unwrap()?;

    if warmup {
        // Warmup reports are intentionally discarded by caller.
    }

    Ok(reports)
}

#[inline]
fn bytes_per_op(bytes: u64, ops: u64) -> f64 {
    if ops == 0 {
        0.0
    } else {
        bytes as f64 / ops as f64
    }
}
```

# Workload: single-row insert

This is the brutal autocommit test.

```rust
pub struct SingleRowInsert {
    pub key_start: i64,
    pub rows_per_actor: i64,
}

impl Workload for SingleRowInsert {
    fn name(&self) -> &'static str {
        "single_row_insert"
    }

    fn setup(&self, engine: &dyn Engine, _cfg: &RunConfig) -> anyhow::Result<()> {
        let mut conn = engine.connect()?;
        conn.execute_batch(
            r#"
            CREATE TABLE IF NOT EXISTS kv (
                k INTEGER PRIMARY KEY,
                v BLOB NOT NULL,
                updated_at INTEGER NOT NULL
            );
            "#,
        )?;
        engine.checkpoint()?;
        Ok(())
    }

    fn run_actor(
        &self,
        ctx: ActorCtx,
        conn: &mut dyn Connection,
    ) -> anyhow::Result<WorkerMetrics> {
        let mut metrics = WorkerMetrics::new()?;
        let mut payload = vec![0_u8; ctx.payload_bytes];

        let actor_base = self.key_start
            + (ctx.actor_id as i64 * self.rows_per_actor);

        let mut n = 0_i64;

        while !ctx.stop.load(std::sync::atomic::Ordering::Acquire) {
            let k = actor_base + n;
            fill_payload(&mut payload, ctx.seed, k as u64);

            let begin = std::time::Instant::now();

            conn.begin(TxMode::Immediate)?;

            let op_start = std::time::Instant::now();
            conn.kv_insert(k, &payload, unix_nanos_i64())?;
            metrics.record_insert(op_start.elapsed().as_nanos() as u64);

            let commit_start = std::time::Instant::now();
            conn.commit()?;
            metrics.record_commit(commit_start.elapsed().as_nanos() as u64);

            std::hint::black_box(begin.elapsed());

            n += 1;
        }

        Ok(metrics)
    }

    fn verify(
        &self,
        _engine: &dyn Engine,
        _cfg: &RunConfig,
    ) -> anyhow::Result<CorrectnessReport> {
        Ok(CorrectnessReport {
            passed: true,
            failures: Vec::new(),
        })
    }
}
```

Payload generation must be deterministic and cheap:

```rust
#[inline]
pub fn fill_payload(buf: &mut [u8], seed: u64, key: u64) {
    let mut x = seed ^ key.wrapping_mul(0x9E37_79B9_7F4A_7C15);

    for chunk in buf.chunks_mut(8) {
        x = splitmix64(x);
        let bytes = x.to_le_bytes();

        for (dst, src) in chunk.iter_mut().zip(bytes.iter()) {
            *dst = *src;
        }
    }
}

#[inline]
pub fn splitmix64(mut x: u64) -> u64 {
    x = x.wrapping_add(0x9E37_79B9_7F4A_7C15);
    let mut z = x;
    z = (z ^ (z >> 30)).wrapping_mul(0xBF58_476D_1CE4_E5B9);
    z = (z ^ (z >> 27)).wrapping_mul(0x94D0_49BB_1331_11EB);
    z ^ (z >> 31)
}

#[inline]
pub fn fast_hash64(bytes: &[u8]) -> u64 {
    let mut h = 0xcbf2_9ce4_8422_2325_u64;
    for &b in bytes {
        h ^= b as u64;
        h = h.wrapping_mul(0x100_0000_01b3);
    }
    h
}

#[inline]
pub fn fast_hash64_i64(v: i64) -> u64 {
    fast_hash64(&v.to_le_bytes())
}
```

# Workload: concurrent writers

This is the most important Phase 9 workload because it targets the main expected RedlineDB advantage.

SQLite WAL has many-reader/single-writer behavior, so disjoint concurrent write transactions should expose its write serialization. RedlineDB should scale better if row locks, index key locks, MVCC, and WAL group commit are working properly. ([SQLite][1])

## Variants

```text
concurrent_writers_disjoint
  each writer owns its own key range
  no logical conflicts expected

concurrent_writers_hotspot
  writers contend for a small key set
  RedlineDB should detect conflicts correctly

concurrent_writers_with_think_time
  writer begins transaction
  reads/updates
  waits 50/250/1000 us inside transaction
  commits
```

The think-time variant is crucial. SQLite’s single writer becomes painful when user code holds a write transaction open. RedlineDB should let disjoint writers progress.

```rust
pub struct ConcurrentWriters {
    pub keyspace_per_actor: i64,
    pub rows_per_tx: usize,
    pub think_inside_tx: std::time::Duration,
    pub disjoint: bool,
}

impl Workload for ConcurrentWriters {
    fn name(&self) -> &'static str {
        "concurrent_writers"
    }

    fn setup(&self, engine: &dyn Engine, cfg: &RunConfig) -> anyhow::Result<()> {
        let mut conn = engine.connect()?;

        conn.execute_batch(
            r#"
            CREATE TABLE IF NOT EXISTS kv (
                k INTEGER PRIMARY KEY,
                v BLOB NOT NULL,
                updated_at INTEGER NOT NULL
            );
            "#,
        )?;

        // Preload enough keys for update-heavy variants.
        let mut payload = vec![0_u8; cfg.payload_bytes];

        for k in 0..cfg.preload_rows as i64 {
            fill_payload(&mut payload, cfg.seed, k as u64);
            conn.begin(TxMode::Immediate)?;
            conn.kv_insert(k, &payload, 0)?;
            conn.commit()?;
        }

        engine.checkpoint()?;
        Ok(())
    }

    fn run_actor(
        &self,
        ctx: ActorCtx,
        conn: &mut dyn Connection,
    ) -> anyhow::Result<WorkerMetrics> {
        let mut metrics = WorkerMetrics::new()?;
        let mut payload = vec![0_u8; ctx.payload_bytes];

        let mut logical_clock = 0_i64;
        let actor_base = if self.disjoint {
            ctx.actor_id as i64 * self.keyspace_per_actor
        } else {
            0
        };

        while !ctx.stop.load(std::sync::atomic::Ordering::Acquire) {
            let tx_start = std::time::Instant::now();

            match conn.begin(TxMode::Immediate) {
                Ok(()) => {}
                Err(e) => {
                    if is_busy_like(&e) {
                        metrics.busy += 1;
                        metrics.retries += 1;
                        backoff(metrics.retries);
                        continue;
                    }
                    return Err(e);
                }
            }

            for i in 0..self.rows_per_tx {
                let k = actor_base + ((logical_clock + i as i64) % self.keyspace_per_actor);
                fill_payload(&mut payload, ctx.seed, k as u64 ^ logical_clock as u64);

                let op_start = std::time::Instant::now();
                conn.kv_update(k, &payload, unix_nanos_i64())?;
                metrics.record_insert(op_start.elapsed().as_nanos() as u64);
            }

            if !self.think_inside_tx.is_zero() {
                std::thread::sleep(self.think_inside_tx);
            }

            let commit_start = std::time::Instant::now();
            match conn.commit() {
                Ok(()) => {
                    metrics.record_commit(commit_start.elapsed().as_nanos() as u64);
                }
                Err(e) => {
                    metrics.failures += 1;
                    let _ = conn.rollback();
                    if is_retryable_conflict(&e) {
                        metrics.retries += 1;
                        continue;
                    }
                    return Err(e);
                }
            }

            std::hint::black_box(tx_start.elapsed());
            logical_clock += self.rows_per_tx as i64;
        }

        Ok(metrics)
    }

    fn verify(&self, _engine: &dyn Engine, _cfg: &RunConfig) -> anyhow::Result<CorrectnessReport> {
        Ok(CorrectnessReport {
            passed: true,
            failures: vec![],
        })
    }
}

fn backoff(retry: u64) {
    let nanos = (retry.min(10) * 100) as u64;
    std::thread::sleep(std::time::Duration::from_nanos(nanos));
}
```

# I/O metering

## RedlineDB I/O metering

RedlineDB should have a storage abstraction like this:

```rust
#[derive(Debug, Clone, Copy)]
pub enum FileKind {
    Data,
    Wal,
    Checkpoint,
    Temp,
    Unknown,
}

pub trait StorageFile: Send + Sync {
    fn read_at(&self, offset: u64, buf: &mut [u8]) -> std::io::Result<usize>;
    fn write_at(&self, offset: u64, buf: &[u8]) -> std::io::Result<usize>;
    fn sync_data(&self) -> std::io::Result<()>;
    fn sync_all(&self) -> std::io::Result<()>;
    fn len(&self) -> std::io::Result<u64>;
}

pub struct MeteredFile<F> {
    inner: F,
    kind: FileKind,
    counters: std::sync::Arc<IoCounters>,
}

pub struct IoCounters {
    pub wal_write_bytes: PaddedAtomicU64,
    pub data_write_bytes: PaddedAtomicU64,
    pub wal_syncs: PaddedAtomicU64,
    pub data_syncs: PaddedAtomicU64,
    pub wal_sync_ns: PaddedAtomicU64,
    pub data_sync_ns: PaddedAtomicU64,
}

impl<F: StorageFile> StorageFile for MeteredFile<F> {
    fn read_at(&self, offset: u64, buf: &mut [u8]) -> std::io::Result<usize> {
        self.inner.read_at(offset, buf)
    }

    fn write_at(&self, offset: u64, buf: &[u8]) -> std::io::Result<usize> {
        let n = self.inner.write_at(offset, buf)?;

        match self.kind {
            FileKind::Wal => self.counters.wal_write_bytes.add(n as u64),
            FileKind::Data => self.counters.data_write_bytes.add(n as u64),
            _ => {}
        }

        Ok(n)
    }

    fn sync_data(&self) -> std::io::Result<()> {
        let start = std::time::Instant::now();
        let r = self.inner.sync_data();
        let ns = start.elapsed().as_nanos() as u64;

        match self.kind {
            FileKind::Wal => {
                self.counters.wal_syncs.add(1);
                self.counters.wal_sync_ns.add(ns);
            }
            FileKind::Data => {
                self.counters.data_syncs.add(1);
                self.counters.data_sync_ns.add(ns);
            }
            _ => {}
        }

        r
    }

    fn sync_all(&self) -> std::io::Result<()> {
        self.sync_data()
    }

    fn len(&self) -> std::io::Result<u64> {
        self.inner.len()
    }
}
```

## SQLite I/O metering

The rigorous way is a custom SQLite VFS wrapper:


```rust
#[repr(C)]
struct MeteredSqliteFile {
    base: ffi::sqlite3_file,
    real: *mut ffi::sqlite3_file,
    methods: *const ffi::sqlite3_io_methods,
    kind: FileKind,
    counters: *const IoCounters,
}

unsafe extern "C" fn metered_x_write(
    file: *mut ffi::sqlite3_file,
    buf: *const std::ffi::c_void,
    amount: c_int,
    offset: ffi::sqlite3_int64,
) -> c_int {
    let mf = file as *mut MeteredSqliteFile;
    let real = (*mf).real;
    let methods = (*mf).methods;

    let start = std::time::Instant::now();

    let rc = ((*methods).xWrite.unwrap())(
        real,
        buf,
        amount,
        offset,
    );

    if rc == ffi::SQLITE_OK {
        let counters = &*(*mf).counters;

        match (*mf).kind {
            FileKind::Wal => counters.wal_write_bytes.add(amount as u64),
            FileKind::Data => counters.data_write_bytes.add(amount as u64),
            _ => {}
        }
    }

    std::hint::black_box(start.elapsed());
    rc
}

unsafe extern "C" fn metered_x_sync(
    file: *mut ffi::sqlite3_file,
    flags: c_int,
) -> c_int {
    let mf = file as *mut MeteredSqliteFile;
    let real = (*mf).real;
    let methods = (*mf).methods;

    let start = std::time::Instant::now();

    let rc = ((*methods).xSync.unwrap())(real, flags);

    let ns = start.elapsed().as_nanos() as u64;
    let counters = &*(*mf).counters;

    match (*mf).kind {
        FileKind::Wal => {
            counters.wal_syncs.add(1);
            counters.wal_sync_ns.add(ns);
        }
        FileKind::Data => {
            counters.data_syncs.add(1);
            counters.data_sync_ns.add(ns);
        }
        _ => {}
    }

    rc
}
```

That is more work, but it is the difference between a serious benchmark and a misleading one.

## Process RSS sampler

```rust
pub struct MemorySampler {
    stop: std::sync::Arc<std::sync::atomic::AtomicBool>,
    handle: Option<std::thread::JoinHandle<anyhow::Result<MemoryReport>>>,
}

impl MemorySampler {
    pub fn start_current_process() -> Self {
        let stop = std::sync::Arc::new(std::sync::atomic::AtomicBool::new(false));
        let stop2 = stop.clone();

        let handle = std::thread::spawn(move || {
            let mut peak = 0_u64;
            let mut final_rss = 0_u64;

            while !stop2.load(std::sync::atomic::Ordering::Acquire) {
                let rss = current_rss_bytes().unwrap_or(0);
                peak = peak.max(rss);
                final_rss = rss;
                std::thread::sleep(std::time::Duration::from_millis(10));
            }

            Ok(MemoryReport {
                configured_cache_bytes: 0,
                peak_rss_bytes: peak,
                final_rss_bytes: final_rss,
                engine_cache_bytes: None,
                dirty_page_bytes: None,
                resident_pages: None,
            })
        });

        Self {
            stop,
            handle: Some(handle),
        }
    }

    pub fn stop(mut self) -> anyhow::Result<MemoryReport> {
        self.stop.store(true, std::sync::atomic::Ordering::Release);
        self.handle.take().unwrap().join().unwrap()
    }
}

#[cfg(target_os = "linux")]
pub fn current_rss_bytes() -> anyhow::Result<u64> {
    let status = std::fs::read_to_string("/proc/self/status")?;

    for line in status.lines() {
        if let Some(rest) = line.strip_prefix("VmRSS:") {
            let kb = rest
                .split_whitespace()
                .next()
                .unwrap_or("0")
                .parse::<u64>()?;
            return Ok(kb * 1024);
        }
    }

    Ok(0)
}
```

# Correctness certification

## Differential SQL tests

Generate SQL that RedlineDB claims to support, run it against both engines, canonicalize results, compare.

```rust
pub struct DifferentialCase {
    pub setup: Vec<String>,
    pub statements: Vec<String>,
    pub final_queries: Vec<String>,
}

pub struct DifferentialRunner {
    pub cases: usize,
    pub seed: u64,
}

impl DifferentialRunner {
    pub fn run(
        &self,
        sqlite: &dyn Engine,
        redline: &dyn Engine,
    ) -> anyhow::Result<CorrectnessReport> {
        let mut failures = Vec::new();

        for case_id in 0..self.cases {
            let case = generate_case(self.seed, case_id as u64);

            let sqlite_result = run_case(sqlite, &case);
            let redline_result = run_case(redline, &case);

            match (sqlite_result, redline_result) {
                (Ok(a), Ok(b)) => {
                    if a != b {
                        failures.push(CorrectnessFailure {
                            case_id,
                            reason: "result mismatch".to_string(),
                            sql: case.statements.join(";\n"),
                            sqlite: Some(format!("{a:?}")),
                            redline: Some(format!("{b:?}")),
                        });
                    }
                }
                (Err(a), Err(b)) => {
                    if !errors_are_equivalent(&a, &b) {
                        failures.push(CorrectnessFailure {
                            case_id,
                            reason: "error mismatch".to_string(),
                            sql: case.statements.join(";\n"),
                            sqlite: Some(a.to_string()),
                            redline: Some(b.to_string()),
                        });
                    }
                }
                (a, b) => {
                    failures.push(CorrectnessFailure {
                        case_id,
                        reason: "success/error mismatch".to_string(),
                        sql: case.statements.join(";\n"),
                        sqlite: Some(format!("{a:?}")),
                        redline: Some(format!("{b:?}")),
                    });
                }
            }
        }

        Ok(CorrectnessReport {
            passed: failures.is_empty(),
            failures,
        })
    }
}
```

Supported SQL generator:

# Crash/recovery certification

## Parent-child model

Crash tests should run the database workload in a child process.

```text
parent starts child
child opens database
child executes transactions
after each commit returns, child prints JSON ack to stdout
parent records ack in oracle file and fsyncs oracle
parent kills child at randomized times
parent reopens database
parent verifies all oracle-acknowledged transactions exist
```

## Why the oracle matters

The invariant is:

```text
If commit returned to the user and parent recorded the ack,
then strict-mode recovery must contain that transaction.
```

## Parent crash driver

```rust
pub fn run_crash_certification(cfg: CrashConfig) -> anyhow::Result<RecoveryReport> {
    let mut passed = 0_u64;
    let mut failed = 0_u64;
    let mut worst_recovery_ns = 0_u64;

    for iteration in 0..cfg.iterations {
        let db_dir = cfg.database_root.join(format!("crash-{iteration}"));
        std::fs::create_dir_all(&db_dir)?;

        let oracle_path = db_dir.join("oracle.jsonl");
        let mut oracle = OracleLog::create(&oracle_path)?;

        let mut child = std::process::Command::new(std::env::current_exe()?)
            .arg("crash-child")
            .arg("--db")
            .arg(&db_dir)
            .arg("--engine")
            .arg(&cfg.engine)
            .arg("--durability")
            .arg(format!("{:?}", cfg.durability))
            .stdout(std::process::Stdio::piped())
            .spawn()?;

        let stdout = child.stdout.take().unwrap();
        let reader = std::io::BufReader::new(stdout);

        let kill_after = randomized_kill_delay(cfg.seed, iteration);

        let parent_start = std::time::Instant::now();

        for line in std::io::BufRead::lines(reader) {
            let line = line?;

            if let Ok(event) = serde_json::from_str::<ChildEvent>(&line) {
                if let ChildEvent::Committed { txn_id, key, value_hash } = event {
                    oracle.append_commit(txn_id, key, value_hash)?;
                }
            }

            if parent_start.elapsed() >= kill_after {
                break;
            }
        }

        let _ = child.kill();
        let _ = child.wait();

        oracle.sync()?;

        let recovery_start = std::time::Instant::now();
        let recovered = reopen_and_verify(&cfg, &db_dir, &oracle)?;
        let recovery_ns = recovery_start.elapsed().as_nanos() as u64;
        worst_recovery_ns = worst_recovery_ns.max(recovery_ns);

        if recovered.passed {
            passed += 1;
        } else {
            failed += 1;
        }
    }

    Ok(RecoveryReport {
        iterations: cfg.iterations,
        passed,
        failed,
        worst_recovery_ns,
        lost_acknowledged_commits: failed,
    })
}
```

# Open-loop latency mode

Closed-loop load answers:

```text
How fast can the database go when clients issue a new request immediately after the previous one finishes?
```

Open-loop load answers:

```text
What happens when requests arrive at a fixed rate regardless of stalls?
```

You want both.

```rust
pub enum LoadMode {
    ClosedLoop,
    OpenLoop {
        target_ops_per_sec_per_actor: f64,
    },
}

pub struct OpenLoopPacer {
    next: std::time::Instant,
    interval: std::time::Duration,
}

impl OpenLoopPacer {
    pub fn new(rate: f64) -> Self {
        let interval = std::time::Duration::from_secs_f64(1.0 / rate);

        Self {
            next: std::time::Instant::now(),
            interval,
        }
    }

    pub fn wait(&mut self) -> u64 {
        self.next += self.interval;
        let now = std::time::Instant::now();

        if self.next > now {
            std::thread::sleep(self.next - now);
            0
        } else {
            // Schedule lag. Record this to detect coordinated omission.
            (now - self.next).as_nanos() as u64
        }
    }
}
```

In open-loop reports, include:

```text
offered_ops_sec
completed_ops_sec

deadline_miss_rate
```

# Checkpoint pressure

SQLite checkpoint behavior is a major part of WAL-mode performance. SQLite readers use an end mark, writers append to WAL, and checkpoints cannot overwrite pages beyond active readers’ end marks; long readers can therefore delay checkpoint completion and cause WAL growth. This deserves a dedicated workload, not a side note. ([SQLite][1])

Benchmark:

```text
1 writer continuously updates rows
N readers perform point/range reads
1 long reader opens transaction and sleeps
checkpoint threshold set low
measure:
  WAL growth
  read latency degradation
  commit stalls
  checkpoint time
  final recovery time
```

Pseudo:

```rust
pub struct CheckpointPressure {
    pub long_reader_hold: std::time::Duration,
    pub checkpoint_every: std::time::Duration,
}

impl Workload for CheckpointPressure {
    fn name(&self) -> &'static str {
        "checkpoint_pressure"
    }

    fn setup(&self, engine: &dyn Engine, cfg: &RunConfig) -> anyhow::Result<()> {
        preload_kv(engine, cfg.preload_rows, cfg.payload_bytes, cfg.seed)?;
        engine.checkpoint()?;
        Ok(())
    }

    fn run_actor(
        &self,
        ctx: ActorCtx,
        conn: &mut dyn Connection,
    ) -> anyhow::Result<WorkerMetrics> {
        if ctx.actor_id == 0 {
            run_long_reader(ctx, conn, self.long_reader_hold)
        } else if ctx.actor_id == 1 {
            run_checkpoint_loop(ctx, conn, self.checkpoint_every)
        } else {
            run_update_loop(ctx, conn)
        }
    }

    fn verify(&self, _engine: &dyn Engine, _cfg: &RunConfig) -> anyhow::Result<CorrectnessReport> {
        Ok(CorrectnessReport {
            passed: true,
            failures: vec![],
        })
    }
}
```

```rust
) -> Vec<GateResult> {
    let mut out = Vec::new();

    let speedup = redline.totals.throughput_ops_sec / sqlite.totals.throughput_ops_sec;

    out.push(GateResult {
        name: "throughput_speedup".to_string(),
        passed: if redline.workload.name == "concurrent_writers" {
            speedup >= gates.min_concurrent_writer_speedup
        } else if redline.config.threads == 1 {
            speedup >= gates.min_single_thread_speedup
        } else {
            true
        },
        observed: speedup,
        required: if redline.workload.name == "concurrent_writers" {
            gates.min_concurrent_writer_speedup
        } else {
            gates.min_single_thread_speedup
        },
    });

    let p99_ratio = redline.latency.op_p99_ns as f64 / sqlite.latency.op_p99_ns.max(1) as f64;

    out.push(GateResult {
        name: "p99_latency_ratio".to_string(),
        passed: p99_ratio <= gates.max_p99_latency_ratio,
        observed: p99_ratio,
        required: gates.max_p99_latency_ratio,
    });

    let memory_ratio = redline.memory.peak_rss_bytes as f64
        / redline.memory.configured_cache_bytes.max(1) as f64;

    out.push(GateResult {
        name: "memory_budget".to_string(),
        passed: memory_ratio <= gates.max_memory_over_budget_ratio,
        observed: memory_ratio,
        required: gates.max_memory_over_budget_ratio,
    });

    out
}

#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct GateResult {
    pub name: String,
    pub passed: bool,
    pub observed: f64,
    pub required: f64,
}
```

I would make the release gates staged:

```text
Gate A: correctness
  zero differential correctness failures
  zero integrity failures
  zero unsupported-feature surprises in declared subset

Gate B: durability
  zero lost acknowledged commits in strict mode
  recovery succeeds after crash workload
  corrupt/torn WAL tails handled

Gate C: single-thread parity
  RedlineDB >= 90% of SQLite on core single-thread OLTP
  RedlineDB p99 <= 125% of SQLite p99

Gate D: concurrent-writer advantage
  RedlineDB >= 2x SQLite WAL on disjoint concurrent writers at 8+ writers
  RedlineDB remains correct under contended writers

Gate E: memory
  peak RSS <= configured cache + allowed overhead
  no unbounded WAL growth under normal checkpoint conditions

Gate F: honesty
  report unsupported SQLite features
  publish exact configs
  publish raw JSON
```

```rust
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct EnvironmentReport {

pub fn collect_environment() -> anyhow::Result<EnvironmentReport> {
    Ok(EnvironmentReport {
        os: std::env::consts::OS.to_string(),
        arch: std::env::consts::ARCH.to_string(),
        rustc: command_output("rustc", &["--version"]).unwrap_or_default(),
        git_sha: command_output("git", &["rev-parse", "HEAD"]).unwrap_or_default(),
        cpu_model: read_cpu_model(),
        cpu_count: std::thread::available_parallelism()
            .map(|n| n.get())
            .unwrap_or(1),
        filesystem: detect_filesystem("."),
        sqlite_version: Some(sqlite_version_string()),
        redlinedb_version: option_env!("CARGO_PKG_VERSION").map(str::to_string),
    })
}

fn sqlite_version_string() -> String {
    unsafe {
        let ptr = ffi::sqlite3_libversion();
        if ptr.is_null() {
            "unknown".to_string()
        } else {
            std::ffi::CStr::from_ptr(ptr)
                .to_string_lossy()
                .into_owned()
        }
    }
}
```

# Anti-cheat checklist

The benchmark should fail or warn if:

```text
SQLite is not actually in WAL mode
SQLite synchronous setting does not match requested durability
RedlineDB durability setting does not match requested mode
page sizes differ
cache sizes differ materially
database is accidentally on tmpfs when not requested
benchmark includes setup time in measurement
prepared statements are not reused
data is not materialized consistently
SELECT without ORDER BY is compared positionally
WAL bytes are inferred only from final file size
RSS exceeds configured budget
SQLite busy errors are silently dropped
RedlineDB conflicts are silently dropped
crash oracle was not fsynced
run has too few operations for stable percentiles
```

---

# SQLite-specific fairness details

Use:

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = FULL | NORMAL | OFF;
PRAGMA wal_autocheckpoint = N;
PRAGMA cache_size = -KIB;
PRAGMA busy_timeout = 5000;
```

Do not use:

```sql
PRAGMA locking_mode = EXCLUSIVE;
```

for the default baseline, because many embedded apps need multiple connections. You may add a separate `sqlite-exclusive` variant, clearly labeled.

Do not force a global Rust mutex around SQLite writes for the main comparison. That hides SQLite’s concurrency model. Instead, include a separately labeled queued-writer baseline.

# What “winning” should look like

For RedlineDB to honestly claim SQLite replacement status:

```text
single-thread point read:
  should be close to SQLite before public claims

single-thread insert:
  should be close in NORMAL and competitive in STRICT

batched insert:
  should match or beat SQLite on large batches

indexed lookup:
  should be close to SQLite, otherwise SQL replacement claim is weak

concurrent readers:
  should not regress badly versus SQLite WAL

concurrent writers:
  should clearly beat SQLite because RedlineDB avoids the single-writer ceiling

checkpoint pressure:
  should have bounded WAL growth and controlled p99 stalls

crash recovery:
  strict mode loses zero acknowledged commits

memory ceiling:
  peak RSS stays within configured bound plus documented overhead
```

The concurrent-writer win is the most important strategic claim. SQLite WAL’s design allows readers and a writer to coexist, but only one writer can be active because writers append to a single WAL. RedlineDB’s benchmark should demonstrate that disjoint writer transactions scale until WAL/device/group-commit limits, not until a global writer lock. ([SQLite][1])

# The one design decision I would be strict about

**Do not let the benchmark suite depend on flattering workloads.**

Include workloads where RedlineDB is expected to lose or struggle:

```text
single-thread point reads
tiny SELECTs
short range scans
small indexed lookups
cache-hot reads
```

SQLite is extremely optimized. If RedlineDB only wins on concurrent writers but loses badly everywhere else, the report should say that. If RedlineDB is close on single-thread and wins big on concurrent writers, then you have a credible replacement story.

That is the real Phase 9: not just “be faster than SQLite,” but **prove exactly where, under what durability mode, at what memory budget, with reproducible evidence**.

[2]: https://sqlite.org/pragma.html "Pragma statements supported by SQLite"
