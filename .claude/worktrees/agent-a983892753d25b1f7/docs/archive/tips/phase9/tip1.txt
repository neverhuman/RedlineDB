Below is how I would build **Phase 9: Benchmark Certification and SQLite Head-to-Head** as a serious release-certification system, not a toy benchmark. The goal is not “produce nice numbers.” The goal is to make RedlineDB’s claims hard to dispute: deterministic workloads, matched durability, matched memory ceilings, repeatable reporting, compatibility checks, crash/recovery validation, and concurrency curves that expose SQLite’s single-writer ceiling.

SQLite in WAL mode is the correct comparator because WAL is SQLite’s faster/concurrent mode: SQLite appends commits to a WAL file, readers can continue from an older snapshot, and readers and writers can proceed concurrently, but SQLite still has only one writer at a time. The upstream docs are explicit that WAL supports concurrent readers/writers while “there can only be one writer at a time,” and the transaction docs say SQLite supports multiple read transactions but only one simultaneous write transaction. ([SQLite][1])

Also, benchmark against a **fixed, recorded SQLite version**. Current upstream SQLite docs mention a rare WAL-reset bug affecting WAL mode with multiple connections writing/checkpointing simultaneously, fixed in SQLite **3.51.3** and later, with some backports. For RedlineDB’s Phase 9, do not compare against an old unfixed SQLite unless the report clearly labels it. ([SQLite][1])

# Core benchmark rules

## 1. Compare modes, not slogans

Do not compare RedlineDB “strict” against SQLite `NORMAL`, or RedlineDB “normal” against SQLite `FULL`.

Use three explicit durability classes:

```rust
pub enum DurabilityClass {
    /// Acknowledged commits must survive process crash and intended power-loss class.
    Strict,

    /// Consistent after process crash; may lose latest commits after power loss.
    Normal,

    /// Developer/unsafe mode. No durability claims.
    Unsafe,
}
```

Map them like this:

```text
Strict:
  RedlineDB: WAL fsync/group commit according to strict durability contract.
  SQLite:   WAL + PRAGMA synchronous=FULL.

Normal:
  RedlineDB: no per-commit fsync, checkpoint/fsync according to normal mode.
  SQLite:   WAL + PRAGMA synchronous=NORMAL.

Unsafe:
  RedlineDB: no durability barriers.
  SQLite:   WAL + PRAGMA synchronous=OFF.
```

SQLite’s own docs say `synchronous=FULL` in WAL mode is ACID, while `NORMAL` in WAL mode is consistent but may lose durability across power loss; in WAL mode `FULL` adds a WAL sync after each transaction commit, whereas `NORMAL` avoids sync operations during most transactions. ([SQLite][2])

## 2. Benchmark through public SQL/API paths

Phase 9 should primarily benchmark the same logical SQL interface users will use:

```sql
INSERT INTO kv(k, v) VALUES (?, ?);
SELECT v FROM kv WHERE k = ?;
UPDATE kv SET v = ? WHERE k = ?;
DELETE FROM kv WHERE k = ?;
SELECT k, v FROM kv WHERE k BETWEEN ? AND ? ORDER BY k LIMIT ?;
```

Kernel-only microbenchmarks are useful diagnostics, but they are not release claims.

## 3. One process, many connections/sessions

The roadmap assumes one owner process per RedlineDB database directory with many sessions/threads. Therefore compare against SQLite as:

```text
SQLite:
  one process
  N SQLite connections
  one connection per worker thread
  WAL mode
  prepared statements per connection

RedlineDB:
  one process
  one shared engine
  N sessions/connections
  one session per worker thread
  prepared statements per session
```

Do **not** share a single SQLite connection across worker threads in the certification path. SQLite’s default threading mode is serialized, which mutex-serializes access to a connection-derived object; use one connection per worker and, if using the raw C API, open with `SQLITE_OPEN_NOMUTEX` while preserving the invariant that a connection is used by exactly one worker thread. SQLite documents serialized mode, the default, and the runtime `SQLITE_OPEN_NOMUTEX` / `SQLITE_OPEN_FULLMUTEX` choice. ([SQLite][3])

## 4. Run SQLite in WAL mode correctly

SQLite setup must be precise:

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = FULL | NORMAL | OFF;
PRAGMA busy_timeout = 5000;
PRAGMA wal_autocheckpoint = 0; -- for controlled-checkpoint benchmarks
PRAGMA cache_size = -N;        -- KiB, per connection
```

For page size tests, set `PRAGMA page_size` before entering WAL mode. SQLite documents that page size cannot be changed after entering WAL mode. ([SQLite][1])

SQLite auto-checkpointing defaults to 1000 WAL pages and can be changed or disabled with `wal_autocheckpoint`; setting it to zero or negative disables auto-checkpointing. ([SQLite][1])

That means Phase 9 needs two checkpoint benchmark families:

```text
Family A: SQLite default-like
  SQLite wal_autocheckpoint = 1000
  RedlineDB equivalent default background/checkpoint threshold

Family B: controlled background checkpoint
  SQLite wal_autocheckpoint = 0
  Benchmark-owned checkpoint thread calls PASSIVE/FULL/RESTART/TRUNCATE as configured
  RedlineDB benchmark-owned checkpoint policy with comparable target bytes/pages
```

SQLite’s docs also warn that checkpointing can cause occasional slower commits when auto-checkpointing is triggered by the committing thread, and that long-running readers can prevent checkpoint completion, causing WAL growth. Those are exactly the behaviors Phase 9 must measure, not hide. ([SQLite][1])

# Benchmark architecture

## High-level design

```text
Benchmark parent process
  |
  |-- reads matrix config
  |-- records machine/build metadata
  |-- spawns one isolated child process per engine/config/repetition
  |-- gathers JSON summaries
  |-- computes ratios, confidence, release gates
  |
  +-- child benchmark process
        |
        |-- opens engine
        |-- configures schema
        |-- loads initial data
        |-- starts sampler thread
        |-- starts optional checkpoint thread
        |-- starts N worker threads
        |-- collects per-worker metrics
        |-- validates final state
        |-- writes raw summary
```

Run each engine/config in a separate child process. This prevents one engine’s allocator, page cache behavior, lingering threads, or leaked memory from polluting the next engine’s run.

Use a parent process for orchestration:

```text
redlinedb_bench run --matrix bench/release.toml --out out/release-2026-04-28
redlinedb_bench child --engine redline --workload ycsb-a --config child.json
redlinedb_bench compare --input out/release-2026-04-28 --format markdown,json
```

# Workload operation model

Use deterministic streaming generation, not huge precomputed traces. Precomputing 100 million operations wastes memory and biases the benchmark toward harness overhead.

```rust
#[derive(Debug, Clone)]
pub enum Op {
    Begin(TxKind),
    Commit,
    Rollback,

    Insert { key: u64, value_seed: u64 },
    PointRead { key: u64 },
    Update { key: u64, value_seed: u64 },
    Delete { key: u64 },
    RangeScan { start: u64, len: u64, limit: usize },
    ReadModifyWrite { key: u64, value_seed: u64 },
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum OpKind {
    Begin,
    Commit,
    Rollback,
    Insert,
    PointRead,
    Update,
    Delete,
    RangeScan,
    ReadModifyWrite,
}

impl Op {
    pub fn kind(&self) -> OpKind {
        match self {
            Op::Begin(_) => OpKind::Begin,
            Op::Commit => OpKind::Commit,
            Op::Rollback => OpKind::Rollback,
            Op::Insert { .. } => OpKind::Insert,
            Op::PointRead { .. } => OpKind::PointRead,
            Op::Update { .. } => OpKind::Update,
            Op::Delete { .. } => OpKind::Delete,
            Op::RangeScan { .. } => OpKind::RangeScan,
            Op::ReadModifyWrite { .. } => OpKind::ReadModifyWrite,
        }
    }
}

pub trait Workload: Send + 'static {
    fn name(&self) -> &'static str;

    fn setup_schema(&self) -> SchemaSpec;

    fn initial_load_rows(&self) -> u64 {
        0
    }

    fn make_generator(&self, worker_id: usize, workers: usize, seed: u64)
        -> Box<dyn OpGenerator>;
}

pub trait OpGenerator: Send {
    fn next_op(&mut self, seq: u64) -> Op;
}
```

Generate values without allocation:

```rust
pub struct ValueMaker {
    scratch: Vec<u8>,
}

impl ValueMaker {
    pub fn new(max_len: usize) -> Self {
        Self {
            scratch: vec![0; max_len],
        }
    }

    pub fn make(&mut self, seed: u64, len: usize) -> &[u8] {
        // Fast deterministic filler. Do not use crypto RNG in hot path.
        let mut x = seed ^ 0x9E37_79B9_7F4A_7C15;
        for chunk in self.scratch[..len].chunks_mut(8) {
            x ^= x >> 12;
            x ^= x << 25;
            x ^= x >> 27;
            let z = x.wrapping_mul(0x2545_F491_4F6C_DD1D);
            let bytes = z.to_le_bytes();
            chunk.copy_from_slice(&bytes[..chunk.len()]);
        }
        &self.scratch[..len]
    }
}
```

# Hot-path metric collection

Never use a global mutex per operation. Use one metrics object per worker, padded to avoid false sharing.

```rust
use hdrhistogram::Histogram;
use serde::{Deserialize, Serialize};

#[repr(align(64))]
pub struct Padded<T>(pub T);

pub struct WorkerMetrics {
    pub worker_id: usize,
    pub successful_ops: u64,
    pub failed_ops: u64,
    pub busy_errors: u64,
    pub tx_commits: u64,
    pub tx_rollbacks: u64,
    pub rows_read: u64,
    pub rows_written: u64,
    pub bytes_read: u64,
    pub bytes_written: u64,
    pub op_latency_ns: Histogram<u64>,
    pub commit_latency_ns: Histogram<u64>,
    pub read_latency_ns: Histogram<u64>,
    pub write_latency_ns: Histogram<u64>,
}

impl WorkerMetrics {
    pub fn new(worker_id: usize) -> Self {
        Self {
            worker_id,
            successful_ops: 0,
            failed_ops: 0,
            busy_errors: 0,
            tx_commits: 0,
            tx_rollbacks: 0,
            rows_read: 0,
            rows_written: 0,
            bytes_read: 0,
            bytes_written: 0,
            op_latency_ns: Histogram::new_with_bounds(1, 60_000_000_000, 3).unwrap(),
            commit_latency_ns: Histogram::new_with_bounds(1, 60_000_000_000, 3).unwrap(),
            read_latency_ns: Histogram::new_with_bounds(1, 60_000_000_000, 3).unwrap(),
            write_latency_ns: Histogram::new_with_bounds(1, 60_000_000_000, 3).unwrap(),
        }
    }

    #[inline]
    pub fn record_op(&mut self, kind: OpKind, elapsed_ns: u64, ok: bool) {
        let _ = self.op_latency_ns.record(elapsed_ns);
        if ok {
            self.successful_ops += 1;
        } else {
            self.failed_ops += 1;
        }

        match kind {
            OpKind::PointRead | OpKind::RangeScan => {
                let _ = self.read_latency_ns.record(elapsed_ns);
            }
            OpKind::Insert | OpKind::Update | OpKind::Delete | OpKind::ReadModifyWrite => {
                let _ = self.write_latency_ns.record(elapsed_ns);
            }
            OpKind::Commit => {
                let _ = self.commit_latency_ns.record(elapsed_ns);
                if ok {
                    self.tx_commits += 1;
                }
            }
            OpKind::Rollback => {
                if ok {
                    self.tx_rollbacks += 1;
                }
            }
            _ => {}
        }
    }
}
```

Use a `NoopEngine` to measure harness overhead. If the fastest database op is 2 µs and the harness costs 200 ns, you are already consuming 10% of the signal. Report this.

# Runner design

The runner should support both fixed-operation and fixed-time runs.

Fixed-operation runs are best for apples-to-apples latency and bytes/op.

Fixed-time runs are best for saturation throughput and steady-state memory/WAL behavior.

```rust
use anyhow::Result;
use std::sync::{
    atomic::{AtomicBool, AtomicU8, Ordering},
    Arc, Barrier,
};
use std::time::{Duration, Instant};

const PHASE_WARMUP: u8 = 0;
const PHASE_MEASURE: u8 = 1;
const PHASE_STOP: u8 = 2;

pub struct RunState {
    pub phase: AtomicU8,
    pub stop: AtomicBool,
}

pub fn run<E: BenchEngine>(cfg: ChildConfig) -> Result<BenchReport> {
    let engine = Arc::new(E::open(&cfg.engine_config)?);

    let workload = workload::build(&cfg.workload)?;
    engine.setup_schema(&workload.setup_schema())?;

    initial_load::<E>(&engine, workload.as_ref(), &cfg)?;

    let sampler = metrics::sampler::Sampler::start(
        cfg.sample_interval_millis,
        cfg.engine_config.db_dir.clone(),
        Arc::clone(&engine),
    );

    let checkpoint_handle =
        checkpoint_worker::maybe_start::<E>(Arc::clone(&engine), cfg.checkpoint.clone());

    let run_state = Arc::new(RunState {
        phase: AtomicU8::new(PHASE_WARMUP),
        stop: AtomicBool::new(false),
    });

    let barrier = Arc::new(Barrier::new(cfg.threads + 1));

    let mut worker_results = Vec::with_capacity(cfg.threads);

    std::thread::scope(|scope| {
        let mut handles = Vec::with_capacity(cfg.threads);

        for worker_id in 0..cfg.threads {
            let engine = Arc::clone(&engine);
            let barrier = Arc::clone(&barrier);
            let run_state = Arc::clone(&run_state);
            let workload_cfg = cfg.workload.clone();
            let cfg_ref = &cfg;

            handles.push(scope.spawn(move || -> Result<WorkerMetrics> {
                let workload = workload::build(&workload_cfg)?;
                let mut generator =
                    workload.make_generator(worker_id, cfg_ref.threads, cfg_ref.seed);
                let mut conn = engine.connect(worker_id)?;
                let mut metrics = WorkerMetrics::new(worker_id);
                let mut value_maker = ValueMaker::new(cfg_ref.max_value_bytes());

                barrier.wait();

                run_worker_loop(
                    worker_id,
                    &mut conn,
                    generator.as_mut(),
                    &run_state,
                    &cfg_ref.warmup,
                    &cfg_ref.measured,
                    &mut value_maker,
                    &mut metrics,
                )?;

                Ok(metrics)
            }));
        }

        barrier.wait();

        drive_phases(&cfg, &run_state)?;

        for handle in handles {
            worker_results.push(handle.join().expect("worker panicked")?);
        }

        Ok::<(), anyhow::Error>(())
    })?;

    if let Some(handle) = checkpoint_handle {
        handle.stop_and_join()?;
    }

    let samples = sampler.stop_and_collect()?;
    let engine_stats = engine.engine_stats()?;

    let validation = validate_final_state::<E>(&engine, &cfg)?;

    let report = BenchReport::from_parts(cfg, worker_results, samples, engine_stats, validation);

    Arc::try_unwrap(engine)
        .ok()
        .expect("all engine references dropped")
        .shutdown()?;

    Ok(report)
}

fn drive_phases(cfg: &ChildConfig, state: &RunState) -> Result<()> {
    match cfg.warmup {
        RunLimit::FixedTime { seconds } => std::thread::sleep(Duration::from_secs(seconds)),
        RunLimit::FixedOps { .. } => {
            // Worker-local handling can mark warmup complete.
            // For simplicity, use time warmup in release matrix.
        }
    }

    state.phase.store(PHASE_MEASURE, Ordering::Release);

    match cfg.measured {
        RunLimit::FixedTime { seconds } => std::thread::sleep(Duration::from_secs(seconds)),
        RunLimit::FixedOps { .. } => {
            // Worker loops stop after their measured op budget.
            while !state.stop.load(Ordering::Acquire) {
                std::thread::sleep(Duration::from_millis(10));
            }
        }
    }

    state.phase.store(PHASE_STOP, Ordering::Release);
    state.stop.store(true, Ordering::Release);
    Ok(())
}
```

Worker loop:

```rust
fn run_worker_loop<C: BenchConnection>(
    _worker_id: usize,
    conn: &mut C,
    generator: &mut dyn OpGenerator,
    state: &RunState,
    warmup: &RunLimit,
    measured: &RunLimit,
    value_maker: &mut ValueMaker,
    metrics: &mut WorkerMetrics,
) -> anyhow::Result<()> {
    let mut seq = 0_u64;
    let mut measured_ops = 0_u64;

    loop {
        let phase = state.phase.load(Ordering::Acquire);
        if phase == PHASE_STOP {
            break;
        }

        let is_measured = phase == PHASE_MEASURE;

        if is_measured {
            if let RunLimit::FixedOps { ops_per_worker } = measured {
                if measured_ops >= *ops_per_worker {
                    state.stop.store(true, Ordering::Release);
                    break;
                }
            }
        } else if let RunLimit::FixedOps { ops_per_worker } = warmup {
            if seq >= *ops_per_worker {
                std::thread::yield_now();
                continue;
            }
        }

        let op = generator.next_op(seq);
        seq += 1;

        let start = std::time::Instant::now();
        let result = execute_op(conn, &op, value_maker);
        let elapsed_ns = start.elapsed().as_nanos().min(u128::from(u64::MAX)) as u64;

        if is_measured {
            metrics.record_op(op.kind(), elapsed_ns, result.is_ok());
            measured_ops += 1;
        }

        result?;
    }

    Ok(())
}

#[inline]
fn execute_op<C: BenchConnection>(
    conn: &mut C,
    op: &Op,
    value_maker: &mut ValueMaker,
) -> anyhow::Result<()> {
    match *op {
        Op::Begin(kind) => conn.begin(kind),
        Op::Commit => conn.commit(),
        Op::Rollback => conn.rollback(),
        Op::Insert { key, value_seed } => {
            let value = value_maker.make(value_seed, 128);
            conn.insert_kv(key, value)
        }
        Op::PointRead { key } => {
            let _ = conn.point_read_kv(key)?;
            Ok(())
        }
        Op::Update { key, value_seed } => {
            let value = value_maker.make(value_seed, 128);
            let _ = conn.update_kv(key, value)?;
            Ok(())
        }
        Op::Delete { key } => {
            let _ = conn.delete_kv(key)?;
            Ok(())
        }
        Op::RangeScan { start, len, limit } => {
            let mut sink = ScanSink::new(limit);
            let _ = conn.range_scan_kv(start, start + len, limit, &mut sink)?;
            Ok(())
        }
        Op::ReadModifyWrite { key, value_seed } => {
            let value = value_maker.make(value_seed, 128);
            conn.read_modify_write_kv(key, value)
        }
    }
}
```

# SQLite raw adapter

For final certification, prefer a raw SQLite adapter instead of `rusqlite` in the hot path. `rusqlite` is fine for development, but certification should minimize wrapper overhead.

```rust
#[cfg(feature = "sqlite")]
pub mod sqlite_raw {
    use super::*;
    use anyhow::{anyhow, bail, Result};
    use libsqlite3_sys::*;
    use std::ffi::{CStr, CString};
    use std::os::raw::c_int;
    use std::path::{Path, PathBuf};
    use std::ptr::{null, null_mut};
    use std::sync::Arc;

    pub struct SqliteEngine {
        path: PathBuf,
        cfg: EngineConfig,
    }

    pub struct SqliteConn {
        db: *mut sqlite3,
        insert: Stmt,
        point_read: Stmt,
        update: Stmt,
        delete: Stmt,
        range_scan: Stmt,
    }

    // Invariant: this connection is moved into exactly one worker thread
    // and is not accessed concurrently.
    unsafe impl Send for SqliteConn {}

    pub struct Stmt {
        ptr: *mut sqlite3_stmt,
    }

    impl BenchEngine for SqliteEngine {
        type Conn = SqliteConn;

        fn open(cfg: &EngineConfig) -> Result<Self> {
            std::fs::create_dir_all(&cfg.db_dir)?;
            let path = cfg.db_dir.join("sqlite.db");

            // Configure database once using a setup connection.
            unsafe {
                let mut setup = open_db(&path, cfg)?;
                configure_sqlite_database(setup.db, cfg, true)?;
                setup.close()?;
            }

            Ok(Self {
                path,
                cfg: cfg.clone(),
            })
        }

        fn setup_schema(&self, schema: &SchemaSpec) -> Result<()> {
            unsafe {
                let mut setup = open_db(&self.path, &self.cfg)?;
                configure_sqlite_database(setup.db, &self.cfg, false)?;

                exec_batch(
                    setup.db,
                    r#"
                    DROP TABLE IF EXISTS kv;
                    CREATE TABLE kv (
                        k INTEGER PRIMARY KEY,
                        v BLOB NOT NULL,
                        version INTEGER NOT NULL DEFAULT 0
                    );
                    "#,
                )?;

                if schema.secondary_index {
                    exec_batch(setup.db, "CREATE INDEX kv_version_idx ON kv(version);")?;
                }

                setup.close()?;
            }
            Ok(())
        }

        fn connect(&self, _worker_id: usize) -> Result<Self::Conn> {
            unsafe {
                let raw = open_db(&self.path, &self.cfg)?;
                configure_sqlite_database(raw.db, &self.cfg, false)?;

                let insert = prepare(
                    raw.db,
                    "INSERT INTO kv(k, v, version) VALUES (?1, ?2, 0);",
                )?;
                let point_read = prepare(raw.db, "SELECT v FROM kv WHERE k = ?1;")?;
                let update = prepare(
                    raw.db,
                    "UPDATE kv SET v = ?1, version = version + 1 WHERE k = ?2;",
                )?;
                let delete = prepare(raw.db, "DELETE FROM kv WHERE k = ?1;")?;
                let range_scan = prepare(
                    raw.db,
                    "SELECT k, v FROM kv WHERE k >= ?1 AND k < ?2 ORDER BY k LIMIT ?3;",
                )?;

                Ok(SqliteConn {
                    db: raw.db,
                    insert,
                    point_read,
                    update,
                    delete,
                    range_scan,
                })
            }
        }

        fn checkpoint(&self, mode: CheckpointMode) -> Result<CheckpointStats> {
            unsafe {
                let mut db = open_db(&self.path, &self.cfg)?;
                let mut log_frames: c_int = 0;
                let mut ckpt_frames: c_int = 0;

                let sqlite_mode = match mode {
                    CheckpointMode::Passive => SQLITE_CHECKPOINT_PASSIVE,
                    CheckpointMode::Full => SQLITE_CHECKPOINT_FULL,
                    CheckpointMode::Restart => SQLITE_CHECKPOINT_RESTART,
                    CheckpointMode::Truncate => SQLITE_CHECKPOINT_TRUNCATE,
                };

                let start = std::time::Instant::now();
                let rc = sqlite3_wal_checkpoint_v2(
                    db.db,
                    null(),
                    sqlite_mode,
                    &mut log_frames,
                    &mut ckpt_frames,
                );
                let elapsed_ns = start.elapsed().as_nanos() as u64;

                let busy = rc == SQLITE_BUSY;
                if rc != SQLITE_OK && rc != SQLITE_BUSY {
                    let err = error_message(db.db);
                    db.close()?;
                    bail!("sqlite checkpoint failed: rc={rc}, {err}");
                }

                db.close()?;

                Ok(CheckpointStats {
                    requested: 1,
                    completed: if busy { 0 } else { 1 },
                    log_frames: log_frames as i64,
                    checkpointed_frames: ckpt_frames as i64,
                    duration_ns: elapsed_ns,
                    busy,
                    ..Default::default()
                })
            }
        }

        fn engine_stats(&self) -> Result<EngineStats> {
            let wal_path = self.path.with_extension("db-wal");
            let wal_bytes = std::fs::metadata(&wal_path).map(|m| m.len()).unwrap_or(0);

            Ok(EngineStats {
                wal_bytes,
                // Extend with sqlite3_status64/db_status64 per connection if desired.
                ..Default::default()
            })
        }

        fn shutdown(self) -> Result<()> {
            Ok(())
        }
    }

    impl BenchConnection for SqliteConn {
        fn begin(&mut self, kind: TxKind) -> Result<()> {
            unsafe {
                match kind {
                    TxKind::ReadOnly => exec_batch(self.db, "BEGIN;"),
                    // BEGIN IMMEDIATE tries to acquire the write transaction up front.
                    TxKind::ReadWrite => exec_batch(self.db, "BEGIN IMMEDIATE;"),
                }
            }
        }

        fn commit(&mut self) -> Result<()> {
            unsafe { exec_batch(self.db, "COMMIT;") }
        }

        fn rollback(&mut self) -> Result<()> {
            unsafe { exec_batch(self.db, "ROLLBACK;") }
        }

        fn insert_kv(&mut self, key: u64, value: &[u8]) -> Result<()> {
            unsafe {
                self.insert.reset()?;
                self.insert.bind_i64(1, key as i64)?;
                self.insert.bind_blob(2, value)?;
                self.insert.step_done(self.db)
            }
        }

        fn point_read_kv(&mut self, key: u64) -> Result<Option<RowDigest>> {
            unsafe {
                self.point_read.reset()?;
                self.point_read.bind_i64(1, key as i64)?;

                match sqlite3_step(self.point_read.ptr) {
                    SQLITE_ROW => {
                        let blob = sqlite3_column_blob(self.point_read.ptr, 0);
                        let len = sqlite3_column_bytes(self.point_read.ptr, 0);
                        let bytes = std::slice::from_raw_parts(blob as *const u8, len as usize);
                        Ok(Some(RowDigest {
                            key,
                            value_hash: fxhash64(bytes),
                            value_len: len as u32,
                        }))
                    }
                    SQLITE_DONE => Ok(None),
                    SQLITE_BUSY => bail!("sqlite busy"),
                    rc => bail!("sqlite point_read failed rc={rc}: {}", error_message(self.db)),
                }
            }
        }

        fn update_kv(&mut self, key: u64, value: &[u8]) -> Result<u64> {
            unsafe {
                self.update.reset()?;
                self.update.bind_blob(1, value)?;
                self.update.bind_i64(2, key as i64)?;
                self.update.step_done(self.db)?;
                Ok(sqlite3_changes64(self.db) as u64)
            }
        }

        fn delete_kv(&mut self, key: u64) -> Result<u64> {
            unsafe {
                self.delete.reset()?;
                self.delete.bind_i64(1, key as i64)?;
                self.delete.step_done(self.db)?;
                Ok(sqlite3_changes64(self.db) as u64)
            }
        }

        fn range_scan_kv(
            &mut self,
            start_key: u64,
            end_key: u64,
            limit: usize,
            sink: &mut ScanSink,
        ) -> Result<usize> {
            unsafe {
                self.range_scan.reset()?;
                self.range_scan.bind_i64(1, start_key as i64)?;
                self.range_scan.bind_i64(2, end_key as i64)?;
                self.range_scan.bind_i64(3, limit as i64)?;

                let mut rows = 0;
                loop {
                    match sqlite3_step(self.range_scan.ptr) {
                        SQLITE_ROW => {
                            let k = sqlite3_column_int64(self.range_scan.ptr, 0) as u64;
                            let blob = sqlite3_column_blob(self.range_scan.ptr, 1);
                            let len = sqlite3_column_bytes(self.range_scan.ptr, 1);
                            let bytes =
                                std::slice::from_raw_parts(blob as *const u8, len as usize);
                            sink.push(RowDigest {
                                key: k,
                                value_hash: fxhash64(bytes),
                                value_len: len as u32,
                            });
                            rows += 1;
                        }
                        SQLITE_DONE => return Ok(rows),
                        SQLITE_BUSY => bail!("sqlite busy"),
                        rc => bail!("sqlite range_scan failed rc={rc}: {}", error_message(self.db)),
                    }
                }
            }
        }

        fn read_modify_write_kv(&mut self, key: u64, value: &[u8]) -> Result<()> {
            self.begin(TxKind::ReadWrite)?;
            let _ = self.point_read_kv(key)?;
            let _ = self.update_kv(key, value)?;
            self.commit()
        }
    }

    struct RawDb {
        db: *mut sqlite3,
    }

    impl RawDb {
        unsafe fn close(&mut self) -> Result<()> {
            if !self.db.is_null() {
                let rc = sqlite3_close(self.db);
                if rc != SQLITE_OK {
                    bail!("sqlite close failed rc={rc}");
                }
                self.db = null_mut();
            }
            Ok(())
        }
    }

    impl Drop for RawDb {
        fn drop(&mut self) {
            unsafe {
                if !self.db.is_null() {
                    let _ = sqlite3_close(self.db);
                    self.db = null_mut();
                }
            }
        }
    }

    unsafe fn open_db(path: &Path, cfg: &EngineConfig) -> Result<RawDb> {
        let mut db: *mut sqlite3 = null_mut();
        let c_path = CString::new(path.to_string_lossy().as_bytes())?;

        let mut flags = SQLITE_OPEN_READWRITE | SQLITE_OPEN_CREATE;
        if cfg.sqlite.open_no_mutex {
            flags |= SQLITE_OPEN_NOMUTEX;
        }
        flags |= SQLITE_OPEN_URI;

        let rc = sqlite3_open_v2(c_path.as_ptr(), &mut db, flags, null());
        if rc != SQLITE_OK {
            let msg = if db.is_null() {
                format!("sqlite open failed rc={rc}")
            } else {
                error_message(db)
            };
            if !db.is_null() {
                sqlite3_close(db);
            }
            bail!(msg);
        }

        sqlite3_busy_timeout(db, cfg.sqlite.busy_timeout_ms as c_int);

        Ok(RawDb { db })
    }

    unsafe fn configure_sqlite_database(
        db: *mut sqlite3,
        cfg: &EngineConfig,
        initial_create: bool,
    ) -> Result<()> {
        if initial_create {
            exec_batch(db, "PRAGMA journal_mode=DELETE;")?;
            exec_batch(db, &format!("PRAGMA page_size={};", cfg.page_size))?;
            exec_batch(db, "VACUUM;")?;
        }

        let mode = query_single_text(db, "PRAGMA journal_mode=WAL;")?;
        if mode.to_ascii_lowercase() != "wal" {
            bail!("SQLite failed to enter WAL mode, got {mode}");
        }

        let sync = match cfg.durability {
            DurabilityClass::Strict => "FULL",
            DurabilityClass::Normal => "NORMAL",
            DurabilityClass::Unsafe => "OFF",
        };
        exec_batch(db, &format!("PRAGMA synchronous={sync};"))?;

        let cache_kib = cfg.cache_bytes / 1024;
        exec_batch(db, &format!("PRAGMA cache_size=-{};", cache_kib))?;

        if cfg.sqlite.temp_store_memory {
            exec_batch(db, "PRAGMA temp_store=MEMORY;")?;
        }

        exec_batch(db, &format!("PRAGMA mmap_size={};", cfg.sqlite.mmap_size))?;

        match cfg.checkpoint {
            CheckpointPolicy::EngineDefault => {
                exec_batch(db, "PRAGMA wal_autocheckpoint=1000;")?;
            }
            _ => {
                exec_batch(db, "PRAGMA wal_autocheckpoint=0;")?;
            }
        }

        Ok(())
    }

    unsafe fn exec_batch(db: *mut sqlite3, sql: &str) -> Result<()> {
        let c_sql = CString::new(sql)?;
        let mut err: *mut i8 = null_mut();
        let rc = sqlite3_exec(db, c_sql.as_ptr(), None, null_mut(), &mut err);
        if rc != SQLITE_OK {
            let msg = if err.is_null() {
                error_message(db)
            } else {
                let s = CStr::from_ptr(err).to_string_lossy().to_string();
                sqlite3_free(err as *mut _);
                s
            };
            bail!("sqlite exec failed rc={rc}: {msg}; sql={sql}");
        }
        Ok(())
    }

    unsafe fn prepare(db: *mut sqlite3, sql: &str) -> Result<Stmt> {
        let c_sql = CString::new(sql)?;
        let mut stmt: *mut sqlite3_stmt = null_mut();
        let rc = sqlite3_prepare_v2(db, c_sql.as_ptr(), -1, &mut stmt, null_mut());
        if rc != SQLITE_OK {
            bail!("sqlite prepare failed rc={rc}: {}", error_message(db));
        }
        Ok(Stmt { ptr: stmt })
    }

    impl Stmt {
        unsafe fn reset(&mut self) -> Result<()> {
            sqlite3_reset(self.ptr);
            sqlite3_clear_bindings(self.ptr);
            Ok(())
        }

        unsafe fn bind_i64(&mut self, idx: c_int, value: i64) -> Result<()> {
            let rc = sqlite3_bind_int64(self.ptr, idx, value);
            if rc != SQLITE_OK {
                bail!("sqlite bind_i64 failed rc={rc}");
            }
            Ok(())
        }

        unsafe fn bind_blob(&mut self, idx: c_int, value: &[u8]) -> Result<()> {
            let rc = sqlite3_bind_blob(
                self.ptr,
                idx,
                value.as_ptr() as *const _,
                value.len() as c_int,
                SQLITE_TRANSIENT(),
            );
            if rc != SQLITE_OK {
                bail!("sqlite bind_blob failed rc={rc}");
            }
            Ok(())
        }

        unsafe fn step_done(&mut self, db: *mut sqlite3) -> Result<()> {
            match sqlite3_step(self.ptr) {
                SQLITE_DONE => Ok(()),
                SQLITE_BUSY => bail!("sqlite busy"),
                rc => bail!("sqlite step failed rc={rc}: {}", error_message(db)),
            }
        }
    }

    impl Drop for Stmt {
        fn drop(&mut self) {
            unsafe {
                if !self.ptr.is_null() {
                    sqlite3_finalize(self.ptr);
                    self.ptr = null_mut();
                }
            }
        }
    }

    impl Drop for SqliteConn {
        fn drop(&mut self) {
            unsafe {
                if !self.db.is_null() {
                    sqlite3_close(self.db);
                    self.db = null_mut();
                }
            }
        }
    }

    unsafe fn query_single_text(db: *mut sqlite3, sql: &str) -> Result<String> {
        let mut stmt = prepare(db, sql)?;
        match sqlite3_step(stmt.ptr) {
            SQLITE_ROW => {
                let text = sqlite3_column_text(stmt.ptr, 0);
                if text.is_null() {
                    Ok(String::new())
                } else {
                    Ok(CStr::from_ptr(text as *const i8)
                        .to_string_lossy()
                        .to_string())
                }
            }
            rc => bail!("query_single_text failed rc={rc}: {}", error_message(db)),
        }
    }

    unsafe fn error_message(db: *mut sqlite3) -> String {
        if db.is_null() {
            return "null sqlite handle".to_string();
        }
        CStr::from_ptr(sqlite3_errmsg(db))
            .to_string_lossy()
            .to_string()
    }

    fn fxhash64(bytes: &[u8]) -> u64 {
        let mut h = 0xcbf2_9ce4_8422_2325_u64;
        for b in bytes {
            h ^= u64::from(*b);
            h = h.wrapping_mul(0x1000_0000_01b3);
        }
        h
    }
}
```

Use `BEGIN IMMEDIATE` for SQLite write transactions in write-heavy benchmarks. It attempts to start the write transaction immediately; SQLite documents that `BEGIN IMMEDIATE` may fail with `SQLITE_BUSY` if another write transaction is already active, and that `EXCLUSIVE` and `IMMEDIATE` are the same in WAL mode. ([SQLite][5])

Also configure a busy timeout and record busy behavior. SQLite’s `sqlite3_busy_timeout` sleeps/retries until the configured time has accumulated, then causes `sqlite3_step()` to return `SQLITE_BUSY`. ([SQLite][6])

# RedlineDB adapter shape

The Redline adapter should be thin. It should not use internal kernel APIs in release certification unless the workload is explicitly marked `kernel_diagnostic`.

```rust
pub mod redline {
    use super::*;
    use anyhow::Result;
    use std::sync::Arc;

    pub struct RedlineEngine {
        inner: Arc<redlinedb::Database>,
    }

    pub struct RedlineConn {
        session: redlinedb::Session,
        insert: redlinedb::PreparedStatement,
        point_read: redlinedb::PreparedStatement,
        update: redlinedb::PreparedStatement,
        delete: redlinedb::PreparedStatement,
        range_scan: redlinedb::PreparedStatement,
    }

    impl BenchEngine for RedlineEngine {
        type Conn = RedlineConn;

        fn open(cfg: &EngineConfig) -> Result<Self> {
            let durability = match cfg.durability {
                DurabilityClass::Strict => redlinedb::Durability::Strict,
                DurabilityClass::Normal => redlinedb::Durability::Normal,

            )?;

            Ok(RedlineConn {
                session,
                insert,
                point_read,
                update,
                delete,
                range_scan,
            })
        }

        fn checkpoint(&self, mode: CheckpointMode) -> Result<CheckpointStats> {
            let start = std::time::Instant::now();
            let stats = self.inner.checkpoint(match mode {
                CheckpointMode::Passive => redlinedb::CheckpointMode::Passive,
                CheckpointMode::Full => redlinedb::CheckpointMode::Full,
                CheckpointMode::Restart => redlinedb::CheckpointMode::Restart,
                CheckpointMode::Truncate => redlinedb::CheckpointMode::Truncate,
            })?;

            Ok(CheckpointStats {
                requested: 1,
                completed: 1,

        fn engine_stats(&self) -> Result<EngineStats> {
            let s = self.inner.stats()?;
            Ok(EngineStats {
                page_cache_hits: s.buffer_pool.hits,
                page_cache_misses: s.buffer_pool.misses,
                dirty_pages: s.buffer_pool.dirty_pages,
                dirty_bytes: s.buffer_pool.dirty_bytes,
                wal_bytes: s.wal.bytes,
                wal_frames: s.wal.frames,

                checkpoint_bytes: s.checkpoint.bytes_written,

                .map_err(|_| anyhow::anyhow!("redline engine still referenced"))?
                .close()?;
            Ok(())
        }
    }

    impl BenchConnection for RedlineConn {
        fn begin(&mut self, kind: TxKind) -> Result<()> {
            match kind {
                TxKind::ReadOnly => self.session.begin_read_only()?,
                TxKind::ReadWrite => self.session.begin()?,
            }
            Ok(())
        }

        fn commit(&mut self) -> Result<()> {
            self.session.commit()?;
            Ok(())
        }

        fn rollback(&mut self) -> Result<()> {
            self.session.rollback()?;
            Ok(())
        }

        fn insert_kv(&mut self, key: u64, value: &[u8]) -> Result<()> {
            self.insert
                .bind_i64(1, key as i64)?
                .bind_blob(2, value)?
                .execute()?;
            Ok(())
        }

        fn point_read_kv(&mut self, key: u64) -> Result<Option<RowDigest>> {
            let mut rows = self.point_read.bind_i64(1, key as i64)?.query()?;
            if let Some(row) = rows.next()? {
                let value = row.blob(0)?;
                Ok(Some(RowDigest {
                    key,
                    value_hash: fxhash64(value),
                    value_len: value.len() as u32,
                }))
            } else {
                Ok(None)
            }
        }

        fn update_kv(&mut self, key: u64, value: &[u8]) -> Result<u64> {
            let n = self
                .update
                .bind_blob(1, value)?
                .bind_i64(2, key as i64)?
                .execute()?;
            Ok(n as u64)
        }

        fn delete_kv(&mut self, key: u64) -> Result<u64> {
            let n = self.delete.bind_i64(1, key as i64)?.execute()?;
            Ok(n as u64)
        }

        fn range_scan_kv(
            &mut self,
            start_key: u64,
            end_key: u64,
            limit: usize,
            sink: &mut ScanSink,
        ) -> Result<usize> {
            let mut rows = self
                .range_scan
                .bind_i64(1, start_key as i64)?
                .bind_i64(2, end_key as i64)?
                .bind_i64(3, limit as i64)?
                .query()?;

            let mut n = 0;
            while let Some(row) = rows.next()? {
                let k = row.i64(0)? as u64;
                let value = row.blob(1)?;
                sink.push(RowDigest {
                    key: k,
                    value_hash: fxhash64(value),
                    value_len: value.len() as u32,
                });
                n += 1;
            }

            Ok(n)
        }

        fn read_modify_write_kv(&mut self, key: u64, value: &[u8]) -> Result<()> {
            self.begin(TxKind::ReadWrite)?;
            let _ = self.point_read_kv(key)?;
            let _ = self.update_kv(key, value)?;
            self.commit()
        }
    }

    fn fxhash64(bytes: &[u8]) -> u64 {
        let mut h = 0xcbf2_9ce4_8422_2325_u64;
        for b in bytes {
            h ^= u64::from(*b);
            h = h.wrapping_mul(0x1000_0000_01b3);
        }
        h
    }
}
```

## 12. Crash recovery

Do this in a child process. Parent observes acknowledged commits through a pipe. Parent kills child at random points, reopens DB, validates all acknowledged transactions.

Process-crash harness:

```text
parent
  creates temp DB dir
  spawns child
  child executes txns
  after each successful COMMIT, child writes Ack{txid, key, value_hash} to stdout pipe
  parent records ack in memory
  parent kills child at pseudo-random ack/time
  parent reopens DB
  parent verifies every acked strict-mode transaction exists
  parent verifies no partial transaction exists
  parent records recovery time
```

For `Strict`, no acknowledged transaction should disappear after process crash. For `Normal`, process crash should still be consistent; power-loss durability is a separate physical/fault-injection claim. SQLite docs distinguish application crash safety from power-loss durability under `synchronous=NORMAL` in WAL mode. ([SQLite][2])

Skeleton:

```rust
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct CommitAck {
    pub txid: u64,
    pub key: u64,
    pub value_hash: u64,
}

pub fn run_crash_parent(cfg: CrashConfig) -> anyhow::Result<CrashReport> {
    let mut child = std::process::Command::new(std::env::current_exe()?)
        .arg("crash-child")
        .arg("--config")
        .arg(cfg.child_config_path.to_string_lossy().to_string())
        .stdout(std::process::Stdio::piped())
        .spawn()?;

    let stdout = child.stdout.take().unwrap();
    let reader = std::io::BufReader::new(stdout);

    let mut acked = Vec::<CommitAck>::new();
    let kill_after = cfg.kill_after_acks;

    for line in std::io::BufRead::lines(reader) {
        let line = line?;
        if let Some(json) = line.strip_prefix("ACK ") {
            let ack: CommitAck = serde_json::from_str(json)?;
            acked.push(ack);

            if acked.len() as u64 >= kill_after {
                kill_process(child.id())?;
                break;
            }
        }
    }

    let _ = child.wait();

    let start = std::time::Instant::now();
    let validation = reopen_and_validate(&cfg.db_dir, &acked)?;
    let recovery_ns = start.elapsed().as_nanos() as u64;

    Ok(CrashReport {
        acked_commits: acked.len() as u64,
        recovered_commits: validation.recovered,
        missing_commits: validation.missing,
        partial_transactions: validation.partial,
        recovery_ns,
    })
}
```

# Compatibility differential testing

Phase 9 needs a SQL compatibility suite that runs supported SQL against both engines and canonicalizes results.

## Rules

1. Only compare supported SQL.
2. Require `ORDER BY` when row order matters.
3. Canonicalize integer/text/blob/null values.
4. Canonicalize floating-point carefully or avoid floats until type semantics are nailed down.
5. Map expected errors into categories, not exact messages.
6. Record unsupported syntax honestly.

```rust
pub fn run_compatibility<E1, E2>(
    redline: &E1,
    sqlite: &E2,
    corpus: &[SqlCase],
) -> anyhow::Result<CompatibilityReport>
where
    E1: SqlExecutor,
    E2: SqlExecutor,
{
    let mut failures = Vec::new();

    for case in corpus {
        let r1 = canonicalize(redline.execute_sql(&case.sql)?);
        let r2 = canonicalize(sqlite.execute_sql(&case.sql)?);

        if !case.accepts(&r1, &r2) {
            failures.push(CompatibilityFailure {
                name: case.name.clone(),
                sql: case.sql.clone(),
                redline: r1,
                sqlite: r2,
            });
        }
    }

    Ok(CompatibilityReport {
        cases: corpus.len(),
        failures,
    })
}
```

# Sampler thread

The sampler observes the process and files without touching the hot path.

```rust
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
pub struct Sample {
    pub elapsed_ms: u64,
    pub rss_bytes: u64,
    pub virtual_bytes: u64,
    pub db_logical_bytes: u64,
    pub db_allocated_bytes: u64,
    pub wal_logical_bytes: u64,
    pub wal_allocated_bytes: u64,
    pub engine: EngineStats,
}

pub struct Sampler {
    stop: std::sync::Arc<std::sync::atomic::AtomicBool>,
    handle: std::thread::JoinHandle<anyhow::Result<Vec<Sample>>>,
}

impl Sampler {
    pub fn start<E: BenchEngine>(
        interval_ms: u64,
        db_dir: std::path::PathBuf,
        engine: std::sync::Arc<E>,
    ) -> Self {
        let stop = std::sync::Arc::new(std::sync::atomic::AtomicBool::new(false));
        let stop2 = stop.clone();

        let handle = std::thread::spawn(move || {
            let start = std::time::Instant::now();
            let mut samples = Vec::new();

            while !stop2.load(std::sync::atomic::Ordering::Acquire) {
                let elapsed_ms = start.elapsed().as_millis() as u64;
                let proc = read_process_memory().unwrap_or_default();
                let fs = read_db_files(&db_dir).unwrap_or_default();
                let engine_stats = engine.engine_stats().unwrap_or_default();

                samples.push(Sample {
                    elapsed_ms,
                    rss_bytes: proc.rss_bytes,
                    virtual_bytes: proc.virtual_bytes,
                    db_logical_bytes: fs.db_logical_bytes,
                    db_allocated_bytes: fs.db_allocated_bytes,
                    wal_logical_bytes: fs.wal_logical_bytes,
                    wal_allocated_bytes: fs.wal_allocated_bytes,
                    engine: engine_stats,
                });

                std::thread::sleep(std::time::Duration::from_millis(interval_ms));
            }

            Ok(samples)
        });

        Self { stop, handle }
    }

    pub fn stop_and_collect(self) -> anyhow::Result<Vec<Sample>> {
        self.stop
            .store(true, std::sync::atomic::Ordering::Release);
        self.handle.join().expect("sampler panicked")
    }
}
```

```rust
pub struct ProcMem {
    pub rss_bytes: u64,
    pub virtual_bytes: u64,

#[cfg(target_os = "linux")]
pub fn read_process_memory() -> std::io::Result<ProcMem> {
    let statm = std::fs::read_to_string("/proc/self/statm")?;
    let mut fields = statm.split_whitespace();

    let pages_total: u64 = fields.next().unwrap_or("0").parse().unwrap_or(0);
    let pages_rss: u64 = fields.next().unwrap_or("0").parse().unwrap_or(0);

    let page_size = unsafe { libc::sysconf(libc::_SC_PAGESIZE) as u64 };

    Ok(ProcMem {
        virtual_bytes: pages_total * page_size,
        rss_bytes: pages_rss * page_size,
    })
}
```

# Release gates

Use gates in this order.

## Gate 1: correctness

Required:

```text
0 compatibility mismatches for supported SQL
0 missing acknowledged commits in strict crash tests
0 partial transactions after crash recovery
0 internal RedlineDB panics
0 validation checksum failures
0 memory-limit violations
```

No performance claim is allowed if this fails.

## Gate 2: benchmark integrity

Required:

```text
SQLite version recorded
RedlineDB git SHA recorded
SQLite compile options recorded
machine CPU/RAM/storage recorded
filesystem recorded
durability mode matched
cache settings recorded
checkpoint policy recorded
warmup/measured duration recorded
raw JSON written
```

## Gate 3: single-thread parity

Before claiming replacement status:

```text
single-thread insert/read/update/range workloads should be near SQLite
no catastrophic p99 regression
WAL bytes/op should be explainable
RSS should be bounded and comparable
```

Do not require RedlineDB to win every single-thread query immediately. Require that any losses are explainable and not structural.

## Gate 4: concurrent-writer advantage

This is where RedlineDB should win clearly.

Required:

```text
disjoint writers scale beyond SQLite at 4/8/16+ writer sessions
p99 latency remains bounded under writer concurrency
writer wait time does not collapse into a global lock
WAL writer/group commit does not become pathological
```

SQLite has a documented single simultaneous write transaction limit, so this is the correct axis for RedlineDB’s architectural advantage. ([SQLite][5])

## Gate 5: memory discipline

Required:

```text
RSS <= configured cache + explicit overhead budget
no unbounded WAL/checkpoint memory growth
long readers do not cause unbounded heap growth
prepared statements/session memory scale linearly and predictably
```

## Gate 6: honesty

The final report must include:

```text
Unsupported SQLite features
Unsupported SQL syntax
Unsupported PRAGMAs
Unsupported typing/collation behavior
Known workloads where SQLite wins
Known workloads where RedlineDB wins
Exact durability semantics
```

# Important fairness details

## SQLite cache matching

Use negative `PRAGMA cache_size` to specify approximate KiB. SQLite documents that negative `cache_size` means approximately `abs(N * 1024)` bytes based on current page size, and that this is a suggested upper bound honored by SQLite’s default page cache. ([SQLite][2])

But note: SQLite cache size is per connection. If RedlineDB has one shared buffer pool and SQLite has 32 connections each with 256 MiB, the comparison is unfair.

Therefore choose one of two modes and label them:

```text
Mode A: per-engine memory budget
  RedlineDB: global buffer pool = 256 MiB
  SQLite: cache_size per connection = 256 MiB / connection_count

Mode B: per-connection default
  RedlineDB: session-local budget + global cache documented
  SQLite: cache_size per connection = N
```

For release claims, prefer **Mode A**.

## Busy/retry policy

Do not silently hide `SQLITE_BUSY`.

Options:

```text
Policy 1: busy_timeout = 0, count busy as failed op
Policy 2: busy_timeout = 5000ms, latency includes wait
Policy 3: benchmark-level retry with backoff, latency includes retries
```

Use Policy 2 for realistic app behavior, but report:

```text
busy errors
busy retries
time spent waiting
operations that exceeded timeout
```

## Checkpoint fairness

Run all checkpoint benchmarks in pairs:

```text
engine_default:
  what a normal user gets

controlled:
  same target WAL bytes
  same checkpoint interval
  same background checkpoint thread policy
```

SQLite checkpoint APIs expose PASSIVE, FULL, RESTART, and TRUNCATE modes; FULL/RESTART can block writers while allowing readers, and PASSIVE avoids waiting but may not complete under concurrent readers/writers. ([SQLite][7])

## Cold vs warm cache

Warm-cache benchmark:

```text
load data
run warmup until cache hit ratio stabilizes or for fixed warmup time
measure
```

Cold-cache benchmark:

```text
use dataset > RAM, or
use unique database file per run, or
drop OS page cache only on controlled Linux machines where allowed
```

Never mix cold RedlineDB with warm SQLite.

## Run order

Randomize and alternate:

```text
rep 0: Redline, SQLite
rep 1: SQLite, Redline
rep 2: Redline, SQLite
...
```

This reduces thermal, filesystem, and background-noise bias.
