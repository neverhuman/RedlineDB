Below is how I would build **Phase 5: SQL Frontend and Execution Engine** in pure Rust, assuming your Phase 1 kernel is already solid and exposes MVCC heap access, row locks, WAL-backed transactions, CSN snapshots, relation metadata, and index primitives from earlier phases.

The main idea: **do not clone SQLite’s whole VDBE design immediately.** Build a compact, Rust-native SQL pipeline:

```text
SQL text
  -> lexer
  -> parser AST
  -> binder / name resolver
  -> bound logical plan
  -> simple rule planner
  -> physical execution tree
  -> expression bytecode VM
  -> kernel cursors / transactions
  -> rows
```

This keeps Phase 5 simple, fast, and extensible. You get prepared statements, autocommit, explicit transactions, MVCC semantics, row-oriented execution, and SQLite-compatible behavior for the subset you support. Later, Phase 6 can replace the rule planner with a cost-based optimizer without changing the public API.

SQLite’s key concurrency limitation to beat is that, even in WAL mode, it still serializes writes: SQLite documents that there can only be a single writer at a time, although WAL mode permits simultaneous readers and writers with snapshot isolation. RedlineDB’s SQL layer must therefore never introduce a global SQL writer mutex; it should rely on the existing kernel’s row locks, key locks, MVCC, and WAL group commit instead. ([SQLite][1])

# 2. Hard design rules

## Rule 1: The SQL layer must not serialize writers

Do not do this:

```rust
// Bad
static SQL_WRITE_LOCK: Mutex<()> = Mutex::new(());
```

The SQL engine should never say, “only one SQL writer at a time.” The kernel already has the real concurrency primitives: row locks, index key locks, MVCC snapshots, WAL group commit, and conflict detection.

The SQL layer’s write path should look like this:

```text
UPDATE statement
  -> open transaction
  -> scan candidate rows through MVCC snapshot
  -> lock candidate row only when needed
  -> recheck current visible row
  -> apply SET expressions
  -> validate constraints
  -> update heap
  -> update indexes
  -> release page latches quickly
  -> hold logical row/key locks until transaction commit
```

DDL may need a schema lock, but DML should not.

## Rule 2: Prepared plans are immutable

A prepared statement should compile once into an immutable plan:

```rust
Arc<PreparedPlan>
```

Then every execution only supplies:

```text
session state
transaction handle
parameter values
execution scratch
```

That lets many sessions reuse the same compiled plan later if you add a plan cache.

## Rule 3: Use schema object IDs, not names, after binding

Parser uses names. Binder resolves names to IDs.

```rust
TableName("users") -> TableId(42)
ColumnName("users.name") -> ColumnId(3)
IndexName("idx_users_email") -> IndexId(9)
```

Physical plans should not perform hash lookups by string during execution.

## Rule 4: Row-oriented API, batch-aware internals

The public API should feel like SQLite:

```rust
while let Some(row) = stmt.step()? {
    // consume row
}
```

But internally, table/index cursors should decode pages in small chunks where possible:

```text
page cursor
  -> visible row iterator
  -> lazy column decoder
  -> expression VM
  -> output row
```

Do not heap-allocate a `Vec<Row>` for every scan.

## Rule 5: Compile expressions into bytecode

Do not recursively walk expression ASTs per row. That is easy but slow.

Instead:

```text
WHERE age > ? AND status = 'active'
```

becomes compact expression bytecode:

```text
COLUMN age
PARAM 1
GT_NUMERIC
COLUMN status
CONST 'active'
EQ_TEXT_BINARY
AND
```

The query executor can remain a physical tree, while expressions use a tiny VM. This is a good “brilliant simplicity” compromise before a full VDBE.

# 3. Kernel boundary assumed by Phase 5

The SQL layer should not know page formats, WAL record formats, or buffer-pool internals. It should depend on a narrow storage API.

Something like:

The critical API is `begin_statement()`. Phase 5 needs statement-level rollback. In an explicit transaction:

```sql
BEGIN;
INSERT INTO t VALUES (1);
INSERT INTO t VALUES (1); -- unique violation
INSERT INTO t VALUES (2);
COMMIT;
```

The failed statement should not necessarily destroy the whole transaction unless the kernel says the error is fatal. The SQL layer needs a savepoint or statement undo boundary.

# 4. Values, SQLite-style typing, and affinities

SQLite’s supported storage classes are `NULL`, `INTEGER`, `REAL`, `TEXT`, and `BLOB`; SQLite also uses dynamic typing, where values carry storage classes and most columns can store values of any storage class. RedlineDB should mirror this for the SQLite-like subset, while keeping stricter internal metadata available for planning and constraints. ([SQLite][2])

Core value type:

```rust
#[derive(Clone, Debug, PartialEq)]
pub enum SqlValue {
    Null,
    Int(i64),
    Real(f64),
    Text(Box<str>),
    Blob(Box<[u8]>),
}

pub enum StorageClass {
    Null,
    Integer,
    Real,
    Text,
    Blob,
}

impl SqlValue {
    #[inline]
    pub fn storage_class(&self) -> StorageClass {
        match self {
            SqlValue::Null => StorageClass::Null,
            SqlValue::Int(_) => StorageClass::Integer,
            SqlValue::Real(_) => StorageClass::Real,
            SqlValue::Text(_) => StorageClass::Text,
            SqlValue::Blob(_) => StorageClass::Blob,
        }
    }
}
```

Use borrowed values internally:


Affinity:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Affinity {
    Blob,
    Text,
    Numeric,
    Integer,
    Real,
}
```

SQLite determines column affinity from declared type strings using substring rules: `INT` gives integer affinity, `CHAR`/`CLOB`/`TEXT` gives text affinity, `BLOB` or no type gives blob affinity, `REAL`/`FLOA`/`DOUB` gives real affinity, and otherwise numeric affinity. RedlineDB should implement those rules exactly for compatibility tests. ([SQLite][2])

```rust
pub fn affinity_from_decl_type(decl: Option<&str>) -> Affinity {
    let Some(decl) = decl else {
        return Affinity::Blob;
    };

    let upper = decl.to_ascii_uppercase();

    if upper.contains("INT") {
        Affinity::Integer
    } else if upper.contains("CHAR") || upper.contains("CLOB") || upper.contains("TEXT") {
        Affinity::Text
    } else if upper.contains("BLOB") {
        Affinity::Blob
    } else if upper.contains("REAL") || upper.contains("FLOA") || upper.contains("DOUB") {
        Affinity::Real
    } else {
        Affinity::Numeric
    }
}
```

Affinity application on insert/update:

```rust
pub fn apply_affinity(v: SqlValue, affinity: Affinity) -> SqlValue {
    match affinity {
        Affinity::Blob => v,

        Affinity::Text => match v {
            SqlValue::Int(i) => SqlValue::Text(i.to_string().into_boxed_str()),
            SqlValue::Real(f) => SqlValue::Text(sql_real_to_text(f).into_boxed_str()),
            other => other,
        },

        Affinity::Numeric | Affinity::Integer => apply_numeric_affinity(v),

        Affinity::Real => match apply_numeric_affinity(v) {
            SqlValue::Int(i) => SqlValue::Real(i as f64),
            other => other,
        },
    }
}

fn apply_numeric_affinity(v: SqlValue) -> SqlValue {
    match v {
        SqlValue::Text(s) => {
            if let Some(i) = parse_well_formed_i64(&s) {
                SqlValue::Int(i)
            } else if let Some(f) = parse_well_formed_f64(&s) {
                if f.is_finite() && f.fract() == 0.0 && f >= i64::MIN as f64 && f <= i64::MAX as f64 {
                    SqlValue::Int(f as i64)
                } else {
                    SqlValue::Real(f)
                }
            } else {
                SqlValue::Text(s)
            }
        }
        other => other,
    }
}

fn sql_real_to_text(f: f64) -> String {
    // Production implementation should match SQLite-style formatting closely enough
    // for differential tests. Start with this, then tune.
    if f.fract() == 0.0 {
        format!("{:.1}", f)
    } else {
        format!("{:.15}", f).trim_end_matches('0').trim_end_matches('.').to_string()
    }
}
```

Do not overdo this initially. Get compatibility for benchmark workloads first, then expand.

# 5. Three-valued SQL boolean logic

SQL boolean logic is not Rust boolean logic.

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Truth {
    True,
    False,
    Unknown,
}

impl Truth {
    #[inline]
    pub fn and(self, rhs: Truth) -> Truth {
        match (self, rhs) {
            (Truth::False, _) | (_, Truth::False) => Truth::False,
            (Truth::True, Truth::True) => Truth::True,
            _ => Truth::Unknown,
        }
    }

    #[inline]
    pub fn or(self, rhs: Truth) -> Truth {
        match (self, rhs) {
            (Truth::True, _) | (_, Truth::True) => Truth::True,
            (Truth::False, Truth::False) => Truth::False,
            _ => Truth::Unknown,
        }
    }

    #[inline]
    pub fn not(self) -> Truth {
        match self {
            Truth::True => Truth::False,
            Truth::False => Truth::True,
            Truth::Unknown => Truth::Unknown,
        }
    }

    #[inline]
    pub fn passes_where(self) -> bool {
        self == Truth::True
    }
}
```

`WHERE NULL` does not pass. `CHECK` usually passes unless false, depending on chosen compatibility semantics.

# 6. Collation and comparison

Start with three collations:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Collation {
    Binary,
    NoCaseAscii,
    RTrim,
}
```

SQLite’s type comparison behavior is unusual and important: sort/comparison order groups `NULL`, numeric values, text, and blobs, and comparison affinity may be applied before comparisons. RedlineDB should encode this in one central module, not scatter conversions through the executor. ([SQLite][2])

```rust
use std::cmp::Ordering;

pub fn compare_sort(a: SqlValueRef<'_>, b: SqlValueRef<'_>, coll: Collation) -> Ordering {
    use SqlValueRef::*;

    match (a, b) {
        (Null, Null) => Ordering::Equal,
        (Null, _) => Ordering::Less,
        (_, Null) => Ordering::Greater,

        (Int(x), Int(y)) => x.cmp(&y),
        (Real(x), Real(y)) => compare_f64_sql(x, y),
        (Int(x), Real(y)) => compare_f64_sql(x as f64, y),
        (Real(x), Int(y)) => compare_f64_sql(x, y as f64),

        (Int(_) | Real(_), Text(_) | Blob(_)) => Ordering::Less,
        (Text(_) | Blob(_), Int(_) | Real(_)) => Ordering::Greater,

        (Text(x), Text(y)) => compare_text(x, y, coll),
        (Text(_), Blob(_)) => Ordering::Less,
        (Blob(_), Text(_)) => Ordering::Greater,
        (Blob(x), Blob(y)) => x.cmp(y),
    }
}

fn compare_f64_sql(a: f64, b: f64) -> Ordering {
    // SQLite does not store NaN as a normal REAL in the same way Rust does.
    // Decide RedlineDB policy explicitly. For now:
    a.partial_cmp(&b).unwrap_or(Ordering::Equal)
}

fn compare_text(a: &str, b: &str, coll: Collation) -> Ordering {
    match coll {
        Collation::Binary => a.as_bytes().cmp(b.as_bytes()),
        Collation::NoCaseAscii => ascii_nocase_cmp(a.as_bytes(), b.as_bytes()),
        Collation::RTrim => {
            let ax = trim_ascii_space_right(a.as_bytes());
            let bx = trim_ascii_space_right(b.as_bytes());
            ax.cmp(bx)
        }
    }
}

fn ascii_nocase_cmp(a: &[u8], b: &[u8]) -> Ordering {
    let n = a.len().min(b.len());
    for i in 0..n {
        let ca = a[i].to_ascii_lowercase();
        let cb = b[i].to_ascii_lowercase();
        match ca.cmp(&cb) {
            Ordering::Equal => {}
            non_eq => return non_eq,
        }
    }
    a.len().cmp(&b.len())
}

fn trim_ascii_space_right(mut s: &[u8]) -> &[u8] {
    while let Some((&last, rest)) = s.split_last() {
        if last == b' ' {
            s = rest;
        } else {
            break;
        }
    }
    s
}
```

For equality and ordering predicates, use comparison affinity:

```rust
pub fn compare_with_affinity(
    left: SqlValueRef<'_>,
    right: SqlValueRef<'_>,
    left_aff: Option<Affinity>,
    right_aff: Option<Affinity>,
    coll: Collation,
) -> Option<Ordering> {
    if matches!(left, SqlValueRef::Null) || matches!(right, SqlValueRef::Null) {
        return None;
    }

    let (l, r) = coerce_for_compare(left, right, left_aff, right_aff);
    Some(compare_sort(l.as_ref(), r.as_ref(), coll))
}
```

Use a small `MaybeOwnedValue` wrapper so coercion does not allocate unless needed.

# 7. Parser architecture

Use a hand-written parser. It is not hard for the Phase 5 subset, and it will be faster and easier to control than a generic SQL parser.

## Lexer goals

The lexer should:

```text
- borrow string slices from the original SQL
- not allocate for normal identifiers
- preserve token spans for diagnostics
- understand parameters: ?, ?NNN, :name, @name, $name
- understand quoted identifiers
- understand string literals
- understand blob literals x'ABCD'
- classify keywords case-insensitively
```

```rust
pub struct Parser<'sql> {
    sql: &'sql str,
    tokens: Vec<Token<'sql>>,
    pos: usize,
    params: ParamCollector<'sql>,
}

impl<'sql> Parser<'sql> {
    pub fn parse_statement(&mut self) -> Result<AstStatement<'sql>> {
        match self.peek_keyword() {
            Some(Keyword::Select) => self.parse_select().map(AstStatement::Select),
            Some(Keyword::Insert) => self.parse_insert().map(AstStatement::Insert),
            Some(Keyword::Update) => self.parse_update().map(AstStatement::Update),
            Some(Keyword::Delete) => self.parse_delete().map(AstStatement::Delete),
            Some(Keyword::Create) => self.parse_create(),
            Some(Keyword::Begin) => self.parse_begin().map(AstStatement::Begin),
            Some(Keyword::Commit) | Some(Keyword::End) => self.parse_commit().map(AstStatement::Commit),
            Some(Keyword::Rollback) => self.parse_rollback().map(AstStatement::Rollback),
            _ => Err(ParseError::new(self.peek_span(), "expected SQL statement").into()),
        }
    }
}
```

Expression parser should be Pratt-style:

```rust
impl<'sql> Parser<'sql> {
    fn parse_expr(&mut self) -> Result<AstExpr<'sql>> {
        self.parse_expr_bp(0)
    }

    fn parse_expr_bp(&mut self, min_bp: u8) -> Result<AstExpr<'sql>> {
        let mut lhs = self.parse_prefix_expr()?;

        loop {
            let Some(op) = self.peek_infix_op() else {
                break;
            };

            let (l_bp, r_bp) = op.binding_power();

            if l_bp < min_bp {
                break;
            }

            self.bump();

            let rhs = self.parse_expr_bp(r_bp)?;
            lhs = AstExpr::Binary {
                op,
                left: Box::new(lhs),
                right: Box::new(rhs),
            };
        }

        Ok(lhs)
    }
}
```

Expression grammar for Phase 5:

```text
literal
parameter
column reference
function call
unary +, -, NOT
binary +, -, *, /, %
=, ==, !=, <>, <, <=, >, >=
IS NULL
IS NOT NULL
AND
OR
parentheses
```

Add `IN`, `BETWEEN`, `LIKE` after the first vertical slice.

# 9. Binder

The binder resolves:

```text
names
table aliases
columns
parameters
function overloads
collations
affinities
result column names
writable vs read-only statement class
```

Parser output:

```sql
SELECT name FROM users WHERE id = ?
```

Bound output:

```text
Project [
  ColumnRef(table=TableId(7), column=ColumnId(2), slot=0)
]
Filter:
  Eq(
    ColumnRef(table=TableId(7), column=ColumnId(1), affinity=Integer),
    Param(1)
  )
Scan TableId(7)
Required columns: id, name
```

Evaluator:

```rust
pub struct EvalCtx<'a, 'row> {
    pub row: Option<RowView<'row>>,
    pub params: &'a [SqlValue],
    pub funcs: &'a FunctionRegistry,
    pub session: &'a SessionState,
}

impl ExprProgram {
    pub fn eval(
        &self,
        ctx: &EvalCtx<'_, '_>,
        scratch: &mut ExprScratch,
    ) -> Result<SqlValue> {
        scratch.clear();

        for op in self.ops.iter() {
            match *op {
                ExprOp::Const(id) => {
                    scratch.stack.push(self.consts[id.0 as usize].clone());
                }

                ExprOp::Param(id) => {
                    let v = ctx.params
                        .get(id.zero_based() as usize)
                        .ok_or(Error::UnboundParameter(id))?;
                    scratch.stack.push(v.clone());
                }

                ExprOp::Column(slot) => {
                    let row = ctx.row.ok_or(Error::Internal("column outside row context"))?;
                    scratch.stack.push(row.get(slot)?.to_owned_value());
                }

                ExprOp::Null => scratch.stack.push(SqlValue::Null),
                ExprOp::True => scratch.stack.push(SqlValue::Int(1)),
                ExprOp::False => scratch.stack.push(SqlValue::Int(0)),

                ExprOp::Not => {
                    let v = pop(&mut scratch.stack)?;
                    scratch.stack.push(match value_to_truth(&v).not() {
                        Truth::True => SqlValue::Int(1),
                        Truth::False => SqlValue::Int(0),
                        Truth::Unknown => SqlValue::Null,
                    });
                }

                ExprOp::Eq { affinity, collation } => {
                    let r = pop(&mut scratch.stack)?;
                    let l = pop(&mut scratch.stack)?;
                    let out = cmp_pred(l.as_ref(), r.as_ref(), affinity, collation, |o| o == Ordering::Equal);
                    scratch.stack.push(truth_to_value(out));
                }

                ExprOp::And => {
                    let r = pop(&mut scratch.stack)?;
                    let l = pop(&mut scratch.stack)?;
                    let out = value_to_truth(&l).and(value_to_truth(&r));
                    scratch.stack.push(truth_to_value(out));
                }

                ExprOp::Or => {
                    let r = pop(&mut scratch.stack)?;
                    let l = pop(&mut scratch.stack)?;
                    let out = value_to_truth(&l).or(value_to_truth(&r));
                    scratch.stack.push(truth_to_value(out));
                }

                ExprOp::Function { func_id, argc } => {
                    let base = scratch.stack.len()
                        .checked_sub(argc as usize)
                        .ok_or(Error::ExpressionStackUnderflow)?;

                    let args = &scratch.stack[base..];
                    let result = ctx.funcs.call(func_id, args, ctx.session)?;
                    scratch.stack.truncate(base);
                    scratch.stack.push(result);
                }

                _ => todo!("remaining expression ops"),
            }
        }

        if scratch.stack.len() != 1 {
            return Err(Error::Internal("expression stack ended with wrong depth"));
        }

        Ok(scratch.stack.pop().unwrap())
    }

    pub fn eval_where(
        &self,
        ctx: &EvalCtx<'_, '_>,
        scratch: &mut ExprScratch,
    ) -> Result<bool> {
        let v = self.eval(ctx, scratch)?;
        Ok(value_to_truth(&v).passes_where())
    }
}

fn pop(stack: &mut Vec<SqlValue>) -> Result<SqlValue> {
    stack.pop().ok_or(Error::ExpressionStackUnderflow)
}

fn truth_to_value(t: Truth) -> SqlValue {
    match t {
        Truth::True => SqlValue::Int(1),
        Truth::False => SqlValue::Int(0),
        Truth::Unknown => SqlValue::Null,
    }
}
```

For the first version, `SqlValue` stack cloning is acceptable. Then optimize:

```text
v1:
  Vec<SqlValue>

v2:
  Small fixed stack for common expressions
  borrowed column refs
  owned only for function/string arithmetic results

v3:
  specialized expression programs for common predicates:
    col = param int
    col = const int
    col > param int
```

The planner can emit specialized filter nodes for ultra-common predicates.

```rust
    pub fn next(&mut self, ctx: &mut ExecCtx<'_>) -> Result<ExecStep> {

            }
        }

}
```

# 19. Project executor

```rust
pub struct ProjectExec {
    input: Box<ExecNode>,
    exprs: Box<[ExprProgram]>,

impl ProjectExec {
    pub fn next(&mut self, ctx: &mut ExecCtx<'_>) -> Result<ExecStep> {
        match self.input.next(ctx)? {
            ExecStep::Row(row) => {

                    row: Some(row.as_view()),

                    funcs: ctx.db.functions(),
                    session: ctx.session,

                let mut out = OutputRow::with_capacity(self.exprs.len());

                }

                Ok(ExecStep::Row(out))
            }

            done @ ExecStep::Done { .. } => Ok(done),
        }
    }
}
```

# 20. Limit executor

```rust
pub struct LimitExec {
    input: Box<ExecNode>,
    limit: Option<ExprProgram>,
    offset: Option<ExprProgram>,
    initialized: bool,
    remaining: u64,
    offset_remaining: u64,
}

impl LimitExec {
    pub fn next(&mut self, ctx: &mut ExecCtx<'_>) -> Result<ExecStep> {
        if !self.initialized {
            self.remaining = eval_limit_expr(self.limit.as_ref(), ctx)?.unwrap_or(u64::MAX);
            self.offset_remaining = eval_limit_expr(self.offset.as_ref(), ctx)?.unwrap_or(0);
            self.initialized = true;
        }

        while self.offset_remaining > 0 {
            match self.input.next(ctx)? {
                ExecStep::Row(_) => self.offset_remaining -= 1,
                done @ ExecStep::Done { .. } => return Ok(done),
            }
        }

        if self.remaining == 0 {
            return Ok(ExecStep::Done { rows_changed: 0 });
        }

        match self.input.next(ctx)? {
            ExecStep::Row(row) => {
                self.remaining -= 1;
                Ok(ExecStep::Row(row))
            }
            done @ ExecStep::Done { .. } => Ok(done),
        }
    }
}
```

# 22. Insert executor

Insert pipeline:

```text
VALUES rows
  -> evaluate each expression
  -> apply defaults for missing columns
  -> apply column affinity
  -> check NOT NULL
  -> check CHECK constraints
  -> encode row
  -> insert heap row
  -> insert index entries
  -> handle unique conflicts
```

```rust
pub struct InsertExec {
    plan: InsertPlan,
    input: Box<ExecNode>,
    done: bool,
    rows_changed: u64,
}

impl InsertExec {
    pub fn next(&mut self, ctx: &mut ExecCtx<'_>) -> Result<ExecStep> {
        if self.done {
            return Ok(ExecStep::Done {
                rows_changed: self.rows_changed,
            });
        }

        let table = ctx.schema.table(self.plan.table_id)?;

        loop {
            match self.input.next(ctx)? {
                ExecStep::Row(input_row) => {
                    let full_row = build_insert_row(table, &self.plan, input_row, ctx)?;

                    validate_not_null(table, &full_row)?;
                    validate_checks(table, &full_row, ctx)?;

                    let encoded = encode_storage_row(table, &full_row)?;
                    let row_id = ctx.tx.insert_row(table.id, encoded)?;

                    for index_id in table.indexes.iter().copied() {
                        let index = ctx.schema.index(index_id)?;
                        let key = encode_index_key(index, &full_row)?;
                        ctx.tx.insert_index_entry(index.id, key, row_id, index.unique)?;
                    }

                    ctx.session.last_insert_rowid = Some(row_id);
                    self.rows_changed += 1;
                }

                ExecStep::Done { .. } => {
                    self.done = true;
                    return Ok(ExecStep::Done {
                        rows_changed: self.rows_changed,
                    });
                }
            }
        }
    }
}
```

Conflict behavior initially:

```text
default: ABORT statement
later: OR IGNORE, OR REPLACE, ON CONFLICT
```

Even with only `ABORT`, the statement savepoint makes behavior usable.

# 23. Update executor

Update is trickier than insert because of MVCC and lost updates.

Correct write flow:

```text
1. Scan rows visible to statement snapshot.
2. For each candidate, evaluate WHERE on snapshot row.
3. Lock row for update.
4. Fetch current row version visible to this transaction.
5. Re-evaluate WHERE on current row.
6. Evaluate SET expressions.
7. Apply affinity and constraints.
8. Update heap row.
9. Maintain indexes.
```

The recheck is critical under concurrent writers.

```rust
pub struct UpdateExec {
    plan: UpdatePlan,
    scan: Box<ExecNode>,
    done: bool,
    rows_changed: u64,
}

impl UpdateExec {
    pub fn next(&mut self, ctx: &mut ExecCtx<'_>) -> Result<ExecStep> {
        if self.done {
            return Ok(ExecStep::Done {
                rows_changed: self.rows_changed,
            });
        }

        let table = ctx.schema.table(self.plan.table_id)?;

        loop {
            match self.scan.next(ctx)? {
                ExecStep::Row(candidate) => {
                    let row_id = candidate.row_id();

                    let locked = ctx.tx.lock_row_for_update(table.id, row_id)?;
                    let current = locked.current_row_view()?;

                    if let Some(pred) = &self.plan.predicate {
                        let eval_ctx = EvalCtx {
                            row: Some(current),
                            params: ctx.params,
                            funcs: ctx.db.functions(),
                            session: ctx.session,
                        };

                        if !pred.eval_where(&eval_ctx, &mut ctx.expr_scratch)? {
                            continue;
                        }
                    }

                    let old_full = materialize_full_row(table, current)?;
                    let mut new_full = old_full.clone();

                    for assignment in self.plan.assignments.iter() {
                        let eval_ctx = EvalCtx {
                            row: Some(current),
                            params: ctx.params,
                            funcs: ctx.db.functions(),
                            session: ctx.session,
                        };

                        let raw = assignment.expr.eval(&eval_ctx, &mut ctx.expr_scratch)?;
                        let col = table.column(assignment.column_id)?;
                        new_full.set(
                            assignment.column_id,
                            apply_affinity(raw, col.affinity),
                        );
                    }

                    validate_not_null(table, &new_full)?;
                    validate_checks(table, &new_full, ctx)?;

                    let encoded_new = encode_storage_row(table, &new_full)?;

                    ctx.tx.update_row(
                        table.id,
                        row_id,
                        locked.version(),
                        encoded_new,
                    )?;

                    maintain_indexes_for_update(
                        ctx.tx,
                        &ctx.schema,
                        table,
                        row_id,
                        &old_full,
                        &new_full,
                    )?;

                    self.rows_changed += 1;
                }

                ExecStep::Done { .. } => {
                    self.done = true;
                    return Ok(ExecStep::Done {
                        rows_changed: self.rows_changed,
                    });
                }
            }
        }
    }
}
```

Index maintenance optimization:

```text
For each index:
  if no indexed column changed:
      skip
  else:
      delete old key
      insert new key
```

# 25. Transaction and session behavior

SQLite automatically starts transactions for SQL statements that access the database, and implicit transactions are committed when the last active statement finishes. It also distinguishes deferred, immediate, and exclusive transactions; in WAL mode, immediate and exclusive behave similarly for write-start behavior. RedlineDB should implement the user-visible subset cleanly while still using its stronger kernel concurrency model. ([SQLite][3])

Session state:


Statement kind:

```rust

    Read,
    Write,
    Ddl,
    TransactionControl,

```

Transaction rules:

```rust
BEGIN:
  - fail if explicit transaction already active
  - DEFERRED: create session marker, but do not open kernel tx until first read/write
  - IMMEDIATE: open read-write kernel tx now
  - EXCLUSIVE: same as IMMEDIATE in RedlineDB embedded MVCC mode for now

SELECT outside explicit tx:
  - open implicit read tx
  - keep it alive until statement reset/finalize/exhausted
  - commit/close automatically

INSERT/UPDATE/DELETE outside explicit tx:
  - open implicit write tx
  - begin statement savepoint
  - execute
  - commit on success
  - rollback on error

SELECT inside explicit tx:
  - use existing tx or open read tx if deferred
  - keep tx until COMMIT/ROLLBACK

WRITE inside explicit tx:
  - upgrade/open write tx
  - begin statement savepoint
  - rollback statement on statement error
  - keep tx active

COMMIT:
  - commit explicit tx
  - publish schema cache if DDL changed
  - fail if abort_only

ROLLBACK:
  - rollback explicit tx
```

Implicit transaction guard:


Cleaner structure:

```rust
impl Connection {
    fn with_statement_tx<R>(
        &mut self,
        kind: StatementKind,
        f: impl FnOnce(&mut dyn KernelTx, &mut SessionState) -> Result<R>,
    ) -> Result<R> {
        if matches!(kind, StatementKind::TransactionControl) {
            return Err(Error::Internal("transaction control should not use statement tx"));
        }

        if self.state.explicit_tx.is_some() {
            return self.with_explicit_tx(kind, f);
        }

        let access = match kind {
            StatementKind::Read => TxAccess::ReadOnly,
            StatementKind::Write | StatementKind::Ddl => TxAccess::ReadWrite,
            StatementKind::TransactionControl => unreachable!(),
        };

        let mut tx = self.db.kernel.begin_tx(TxOptions {
            access,
            isolation: self.state.default_isolation,
            durability: self.state.durability,
            explicit: false,
        })?;

        let sp = if matches!(kind, StatementKind::Write | StatementKind::Ddl) {
            Some(tx.begin_statement()?)
        } else {
            None
        };

        let result = f(tx.as_mut(), &mut self.state);

        match result {
            Ok(v) => {
                tx.commit()?;
                Ok(v)
            }
            Err(e) => {
                if let Some(sp) = sp {
                    let _ = tx.rollback_statement(sp);
                }
                let _ = tx.rollback();
                Err(e)
            }
        }
    }
}
```

For `SELECT`, the transaction cannot commit until the cursor is exhausted or reset. Therefore `Statement::step()` should own the implicit transaction while running.

Step:

```rust
impl Statement {
    pub fn step(&mut self, conn: &mut Connection) -> Result<Option<RowRef<'_>>> {
        if matches!(self.state, StatementRuntime::Prepared) {
            self.start(conn)?;
        }

        let StatementRuntime::Running(running) = &mut self.state else {
            return Ok(None);
        };

        let mut ctx = running.make_ctx(conn, &self.params)?;

        match running.root.next(&mut ctx)? {
            ExecStep::Row(row) => {
                self.store_current_row(row);
                Ok(Some(self.current_row_ref()))
            }

            ExecStep::Done { rows_changed } => {
                running.rows_changed += rows_changed;
                self.finish_success(conn)?;
                Ok(None)
            }
        }
    }

    pub fn reset(&mut self, conn: &mut Connection) -> Result<()> {
        match std::mem::replace(&mut self.state, StatementRuntime::Prepared) {
            StatementRuntime::Running(mut running) => {
                running.close(conn)?;
            }
            _ => {}
        }

        self.clear_current_row();
        Ok(())
    }
}
```

Public API should make it hard to misuse the same connection concurrently. In Rust:

```rust
impl Connection {
    pub fn prepare(&mut self, sql: &str) -> Result<Statement>;
}
```

Then `Statement::step(&mut self, conn: &mut Connection)` is awkward but safe.

Better ergonomic design:

```rust
pub struct Statement<'conn> {
    conn: &'conn mut Connection,
    inner: StatementInner,
}
```

That prevents using the connection while the statement is alive.

But SQLite allows multiple prepared statements on one connection. To support that later, use interior session handles carefully. For Phase 5, I would choose correctness and simplicity:

```rust
let mut stmt = conn.prepare("SELECT ...")?;
while let Some(row) = stmt.step()? {}
```

`Statement` borrows the connection mutably. Multiple concurrent statements require multiple connections, which is exactly what you want for concurrent workloads.

# 28. DDL execution

DDL is transactional.

`CREATE TABLE`:

```text
parse DDL
bind and validate
open write tx
write catalog rows
allocate relation storage
create implicit primary-key index if needed
commit
publish new schema cache
```

Executor:

```rust
pub struct CreateTableExec {
    plan: CreateTablePlan,
    done: bool,
}

impl CreateTableExec {
    pub fn next(&mut self, ctx: &mut ExecCtx<'_>) -> Result<ExecStep> {
        if self.done {
            return Ok(ExecStep::Done { rows_changed: 0 });
        }

        let mutation = CatalogMutation::CreateTable {
            table: self.plan.table_def.clone(),
        };

        ctx.tx.apply_catalog_mutation(mutation)?;

        ctx.session.schema_dirty = true;
        self.done = true;

        Ok(ExecStep::Done { rows_changed: 0 })
    }
}
```

`CREATE INDEX` on existing table:

```text
1. write catalog intent row: index exists but not ready
2. scan table at transaction snapshot
3. insert index entries
4. mark index ready
5. commit
6. publish schema
```

If crash occurs mid-build, recovery should see either:

```text
index not committed
```

or:

```text
index committed and ready
```

Never expose a half-built ready index.

For Phase 5, it is acceptable for `CREATE INDEX` to block writes to that table while building. Do not block unrelated tables.

# 33. Memory strategy

## Prepare path

Use normal allocation. It is not hot compared to stepping millions of rows.

Still, avoid pathological behavior:

```text
- AST nodes allocated in arena or Vec-backed boxes
- identifiers normalized once
- bound plans store compact IDs
- physical plans compile expression bytecode
```

## Execute path

Execution should allocate almost nothing.

Per statement:

```rust
pub struct StatementScratch {
    expr: ExprScratch,
    row: RowScratch,
    output: OutputRow,
    sort: SortScratch,
}
```

Reuse it across resets.

Memory caps:

```rust
pub struct SqlMemoryConfig {
    pub statement_memory_limit: usize,
    pub sort_memory_limit: usize,
    pub max_result_row_bytes: usize,
    pub max_sql_length: usize,
    pub max_expression_depth: usize,
    pub max_columns: usize,
    pub max_params: usize,
}
```

Use bounded external sort. Do not let:

```sql
SELECT * FROM huge_table ORDER BY huge_text_col;
```

consume unbounded memory.

## String/blob policy

Internal:

```text
- Borrow from row storage during expression evaluation.
- Own values only when:
  - result row is returned to user
  - expression creates new text/blob
  - parameter stores text/blob
  - sort materializes rows
```

## Column decoding

Use required-column bitsets:


The binder/planner computes exactly which columns are needed for:

```text

projection

```

Table scan asks kernel only for those.

Public rule:

```text
Database: Send + Sync
```

```text

same schema:
  DDL schema lock contention
```

Everything else should scale.

# 35. Isolation behavior

Support two isolation modes:

```rust
pub enum Isolation {
    Snapshot,
    ReadCommitted,
}
```

Snapshot:

```text
BEGIN;
SELECT ...;  -- establishes snapshot
SELECT ...;  -- same snapshot
COMMIT;
```

Read committed:

```text
BEGIN;
SELECT ...;  -- statement snapshot A
SELECT ...;  -- statement snapshot B
COMMIT;
```

Default should be snapshot isolation for SQLite WAL-like behavior, because SQLite WAL readers see an unchanging snapshot from the start of the read transaction. ([SQLite][1])

For write transactions, RedlineDB should use kernel conflict detection:

```text
read row version V
concurrent writer commits V+1
this tx tries update based on V
  -> conflict or recheck depending isolation/write policy
```

For Phase 5, choose:

```text
UPDATE/DELETE:
  lock current row
  recheck predicate
  write current row
```

This gives good read committed write behavior. For strict snapshot isolation, kernel may return serialization/conflict errors.

# 40. Constraint enforcement

Column constraints:

```text

  after default and affinity

  when column omitted

  after full row assembled

  via unique index insert
```

```rust
fn build_insert_row(
    table: &TableDef,
    plan: &InsertPlan,
    input: OutputRow,
    ctx: &mut ExecCtx<'_>,
) -> Result<FullRow> {
    let mut row = FullRow::nulls(table.columns.len());

    for col in table.columns.iter() {
        if let Some(default) = &col.default {
            row.set(col.id, eval_default(default, ctx)?);
        }
    }

    for (target_col, input_value) in plan.target_columns.iter().zip(input.values) {
        let col = table.column(*target_col)?;
        row.set(*target_col, apply_affinity(input_value, col.affinity));
    }

    Ok(row)
}
```

```rust
fn validate_checks(
    table: &TableDef,
    row: &FullRow,
    ctx: &mut ExecCtx<'_>,
) -> Result<()> {
    let row_view = RowView::from_full_row(row);

    for constraint in table.constraints.iter() {
        if let ConstraintDef::Check { name, expr } = constraint {
            let eval_ctx = EvalCtx {
                row: Some(row_view),
                params: ctx.params,
                funcs: ctx.db.functions(),
                session: ctx.session,
            };

            let v = expr.eval(&eval_ctx, &mut ctx.expr_scratch)?;
            let truth = value_to_truth(&v);

            if truth == Truth::False {
                return Err(Error::CheckViolation {
                    table: table.name.display().into(),
                    constraint: name.as_ref().map(|n| n.display().into()),
                });
            }
        }
    }

    Ok(())
}
```

# 41. `CREATE TABLE` binder

```rust
fn bind_create_table(
    ctx: &mut BindCtx<'_>,
    ast: AstCreateTable<'_>,
) -> Result<BoundCreateTable> {
    let table_name = bind_ident(ast.name);

    if ctx.schema.table_by_name(&table_name).is_some() && !ast.if_not_exists {
        return Err(Error::TableAlreadyExists(table_name.display().into()));
    }

    let mut columns = Vec::new();
    let mut seen = HashSet::new();

    for (ordinal, c) in ast.columns.into_iter().enumerate() {
        let name = bind_ident(c.name);

        if !seen.insert(name.key().clone()) {
            return Err(Error::DuplicateColumn(name.display().into()));
        }

        let affinity = affinity_from_decl_type(c.type_name);
        let mut nullable = true;
        let mut default = None;
        let mut primary_key = false;
        let mut unique = false;
        let mut checks = Vec::new();

        for constraint in c.constraints {
            match constraint {
                AstColumnConstraint::PrimaryKey => {
                    primary_key = true;
                    nullable = false;
                }
                AstColumnConstraint::NotNull => nullable = false,
                AstColumnConstraint::Unique => unique = true,
                AstColumnConstraint::Default(expr) => {
                    default = Some(bind_default_expr(ctx, expr)?);
                }
                AstColumnConstraint::Check(expr) => {
                    checks.push(bind_check_expr(ctx, expr)?);
                }
            }
        }

        columns.push(BoundColumnDef {
            name,
            ordinal: ordinal as u16,
            declared_type: c.type_name.map(Into::into),
            affinity,
            nullable,
            default,
            primary_key,
            unique,
            checks,
        });
    }

    Ok(BoundCreateTable {
        name: table_name,
        columns: columns.into_boxed_slice(),
        table_constraints: bind_table_constraints(ctx, ast.constraints)?,
    })
}
```

# 42. `SELECT` binder

For one-table Phase 5:

```rust
fn bind_select(ctx: &mut BindCtx<'_>, ast: AstSelect<'_>) -> Result<BoundSelect> {
    let source = if let Some(from) = ast.from {
        let table_name = bind_ident(from.table);
        let table = ctx.schema
            .table_by_name(&table_name)
            .ok_or_else(|| Error::NoSuchTable(table_name.display().into()))?
            .clone();

        let alias = from.alias
            .map(bind_ident)
            .unwrap_or_else(|| table.name.clone());

        ctx.scopes.push(Scope::from_table(alias, table.clone()));

        Some(BoundTableSource {
            table_id: table.id,
            table_name: table.name.clone(),
            required_columns: ColumnSet::empty(table.columns.len()),
        })
    } else {
        None
    };

    let predicate = match ast.where_clause {
        Some(expr) => Some(bind_expr(ctx, expr)?),
        None => None,
    };

    let mut outputs = Vec::new();

    for item in ast.projection {
        match item {
            AstSelectItem::Star => {
                expand_star(ctx, &mut outputs)?;
            }
            AstSelectItem::QualifiedStar(q) => {
                expand_qualified_star(ctx, q, &mut outputs)?;
            }
            AstSelectItem::Expr { expr, alias } => {
                let bound = bind_expr(ctx, expr)?;
                let name = alias
                    .map(bind_ident)
                    .map(|i| i.display().into())
                    .unwrap_or_else(|| derive_output_name(&bound));
                outputs.push(BoundOutputColumn { name, expr: bound });
            }
        }
    }

    let order_by = ast.order_by
        .into_iter()
        .map(|o| bind_order_expr(ctx, o))
        .collect::<Result<Vec<_>>>()?;

    let limit = ast.limit.map(|e| bind_expr(ctx, e)).transpose()?;
    let offset = ast.offset.map(|e| bind_expr(ctx, e)).transpose()?;

    ctx.scopes.pop();

    Ok(BoundSelect {
        output: outputs.into_boxed_slice(),
        source,
        predicate,
        order_by: order_by.into_boxed_slice(),
        limit,
        offset,
    })
}
```

After binding, walk all expressions and mark required columns.

# 43. Planning SELECT

```rust
fn plan_select(bound: BoundSelect, schema: &SchemaCache) -> Result<PhysicalPlan> {
    let mut plan = if let Some(source) = bound.source {
        let table = schema.table(source.table_id)?;

        let split = bound.predicate
            .as_ref()
            .map(split_predicate)
            .unwrap_or_default();

        let access = choose_access_path(table, &split, schema);

        let mut p = access_path_to_physical(access, source.required_columns, schema)?;

        if let Some(residual) = split.residual {
            p = PhysicalPlan::Filter(FilterPlan {
                input: Box::new(p),
                predicate: compile_expr(residual)?,
            });
        }

        p
    } else {
        PhysicalPlan::Values(ValuesPlan {
            rows: Box::new([Box::new([])]),
        })
    };

    if !bound.output.is_empty() {
        let exprs = bound.output
            .iter()
            .map(|o| compile_expr(o.expr.clone()))
            .collect::<Result<Vec<_>>>()?
            .into_boxed_slice();

        plan = PhysicalPlan::Project(ProjectPlan {
            input: Box::new(plan),
            exprs,
        });
    }

    if !bound.order_by.is_empty() {
        plan = PhysicalPlan::Sort(SortPlan {
            input: Box::new(plan),
            keys: compile_sort_keys(bound.order_by)?,
            memory_limit: schema.config.sort_memory_limit,
        });
    }

    if bound.limit.is_some() || bound.offset.is_some() {
        plan = PhysicalPlan::Limit(LimitPlan {
            input: Box::new(plan),
            limit: bound.limit.map(compile_expr).transpose()?,
            offset: bound.offset.map(compile_expr).transpose()?,
        });
    }

    Ok(plan)
}
```

Optimization: `ORDER BY` should be before `Project` unless order expressions reference output aliases. Internally, keep hidden columns until sort.

Better physical order:

```text
Scan
Filter
Sort
Project
Limit or Limit before Project depending expressions
```

For `ORDER BY ... LIMIT`, push limit into sort.

# 44. Fast index path

Special-case primary key lookups:

```rust
pub struct PrimaryKeyLookupExec {
    table_id: TableId,
    key: ExprProgram,
    opened: bool,
    emitted: bool,
    cursor: Option<Box<dyn KernelRowCursor>>,
}

impl PrimaryKeyLookupExec {
    pub fn next(&mut self, ctx: &mut ExecCtx<'_>) -> Result<ExecStep> {
        if self.emitted {
            return Ok(ExecStep::Done { rows_changed: 0 });
        }

        if !self.opened {
            let eval_ctx = EvalCtx {
                row: None,
                params: ctx.params,
                funcs: ctx.db.functions(),
                session: ctx.session,
            };

            let key_value = self.key.eval(&eval_ctx, &mut ctx.expr_scratch)?;
            let encoded = encode_pk_key(key_value)?;

            self.cursor = Some(ctx.tx.open_index_scan(
                primary_index_for(self.table_id),
                IndexBounds::point(encoded),
                self.projection,
            )?);

            self.opened = true;
        }

        let cursor = self.cursor.as_mut().unwrap();

        match cursor.next()? {
            Some(row) => {
                self.emitted = true;
                Ok(ExecStep::Row(OutputRow::from_kernel_row(row)?))
            }
            None => {
                self.emitted = true;
                Ok(ExecStep::Done { rows_changed: 0 })
            }
        }
    }
}
```

For `SELECT ... WHERE rowid = ?`, this should be extremely fast.

# 49. The most important performance tricks

## 1. Precompute everything at prepare time

Do not compute this per row:

```text
column name lookup
function name lookup
operator dispatch from AST
affinity of column
collation of comparison
required column set
index choice
parameter position
```

## 2. Use IDs and ordinals

Per row, use:

```text
InputSlot(0)
InputSlot(1)
```

not:

```text
"users.name"
```

## 3. Use expression bytecode

Avoid recursive expression evaluation.

## 4. Use specialized physical nodes

Do not make a primary-key lookup pass through generic table scan machinery.

## 5. Keep latches short

SQL execution must not hold page latches while:

```text
evaluating user expressions
waiting on row locks
waiting on WAL fsync
sorting
calling functions
```

Kernel cursors should copy or pin what is needed, release page latch, then return row view.

## 6. Make autocommit cheap

Autocommit insert is common. The path should be:

```text
prepare cached insert
bind values
begin tx
encode row
insert heap
insert indexes
commit via group commit
reset
```

No schema lookup. No parser. No planner. No per-row heap churn.

## 7. Separate DDL locks from DML locks

A schema lock is fine for:

```text
CREATE TABLE
DROP TABLE
CREATE INDEX
DROP INDEX
```

It is not fine for:

```text
INSERT
UPDATE
DELETE
SELECT
```

DML should run against an immutable schema snapshot.

```rust
            kind: physical.statement_kind(),
            param_count: physical.param_count(),
            outputs: physical.output_columns(),
```

# 51. End-to-end execution path

```rust
impl<'conn> Statement<'conn> {
    pub fn step(&mut self) -> Result<Option<Row<'_>>> {
        self.ensure_started()?;

        let runtime = match &mut self.runtime {
            StatementRuntime::Running(r) => r,
            StatementRuntime::Done => return Ok(None),
            StatementRuntime::Prepared => unreachable!(),
            StatementRuntime::Failed => return Err(Error::StatementFailed),
        };

        let step = runtime.root.next(&mut runtime.ctx)?;

        match step {
            ExecStep::Row(row) => {
                self.current_row = Some(row);
                Ok(Some(Row {
                    inner: self.current_row.as_ref().unwrap(),
                }))
            }

            ExecStep::Done { rows_changed } => {
                self.conn.state.changes = rows_changed;
                self.conn.state.total_changes += rows_changed;

                runtime.finish_success(&mut self.conn.state)?;
                self.runtime = StatementRuntime::Done;

                Ok(None)
            }
        }
    }
}
```

# 52. Transaction control statements

`BEGIN` executor:

```rust
fn exec_begin(conn: &mut Connection, mode: TxMode) -> Result<()> {
    if conn.state.explicit_tx.is_some() {
        return Err(Error::TransactionAlreadyActive);
    }

    match mode {
        TxMode::Deferred => {
            conn.state.explicit_tx = Some(ExplicitTx::deferred());
        }

        TxMode::Immediate | TxMode::Exclusive => {
            let tx = conn.db.kernel.begin_tx(TxOptions {
                access: TxAccess::ReadWrite,
                isolation: conn.state.default_isolation,
                durability: conn.state.durability,
                explicit: true,
            })?;

            conn.state.explicit_tx = Some(ExplicitTx {
                mode,
                tx,
                started_write: true,
                abort_only: false,
            });
        }
    }

    conn.state.autocommit = false;
    Ok(())
}
```

`COMMIT`:

```rust
fn exec_commit(conn: &mut Connection) -> Result<()> {
    let Some(explicit) = conn.state.explicit_tx.take() else {
        return Err(Error::NoActiveTransaction);
    };

    if explicit.abort_only {
        explicit.tx.rollback()?;
        conn.state.autocommit = true;
        return Err(Error::TransactionAbort);
    }

    let schema_dirty = conn.state.schema_dirty;

    explicit.tx.commit()?;
    conn.state.autocommit = true;

    if schema_dirty {
        conn.db.reload_schema_cache()?;
        conn.state.schema_dirty = false;
    }

    Ok(())
}
```

`ROLLBACK`:

```rust
fn exec_rollback(conn: &mut Connection) -> Result<()> {
    let Some(explicit) = conn.state.explicit_tx.take() else {
        return Err(Error::NoActiveTransaction);
    };

    explicit.tx.rollback()?;
    conn.state.autocommit = true;
    conn.state.schema_dirty = false;

    Ok(())
}
```

# 53. Concurrency examples RedlineDB should pass

## Readers should not block writers

```sql
-- conn 1
BEGIN;
SELECT * FROM t WHERE id BETWEEN 1 AND 100000;

-- conn 2
UPDATE t SET v = v + 1 WHERE id = 999999;
COMMIT;
```

Expected:

```text
conn 1 continues on old snapshot
conn 2 commits
no global writer/read lock conflict
```

## Disjoint writers should proceed concurrently

```sql
-- conn 1
UPDATE t SET v = v + 1 WHERE id = 1;

-- conn 2
UPDATE t SET v = v + 1 WHERE id = 2;
```

Expected:

```text
both can be active
WAL append serializes only physical logging, ideally via group commit
row locks do not conflict
```

## Conflicting writers should serialize only on row/key

```sql
-- conn 1
UPDATE t SET v = v + 1 WHERE id = 1;

-- conn 2
UPDATE t SET v = v + 1 WHERE id = 1;
```

Expected:

```text
conn 2 waits, returns busy, or detects conflict depending lock policy
no unrelated table/index blocked
```

# 56. The concise internal architecture

```text
RedlineDb
  Arc<DatabaseHandle>
    Arc<Kernel>
    Arc<FunctionRegistry>
    ArcSwap<SchemaCache>
    DbConfig

Connection
  SessionState
  no global locks

Statement
  Arc<PreparedPlan>
  params Vec<SqlValue>
  runtime ExecNode
  scratch memory

PreparedPlan
  schema_version
  param_count
  output columns
  PhysicalPlan

PhysicalPlan
  immutable
  expression bytecode
  table/index IDs
  column ordinals

ExecNode
  stateful
  pulls rows
  talks to KernelTx
```

That design keeps the SQL layer boring in the best way: immutable plans, explicit execution state, no hidden global locks, no page knowledge, no unbounded memory surprises, and no unnecessary per-row allocation.

# 57. Practical “first commit” implementation target

The first serious implementation should support this complete script:

```sql
CREATE TABLE users(
    id INTEGER PRIMARY KEY,
    email TEXT NOT NULL,
    age INTEGER DEFAULT 0,
    active INTEGER DEFAULT 1
);

CREATE UNIQUE INDEX users_email ON users(email);

BEGIN;
INSERT INTO users(id, email, age) VALUES (1, 'a@example.com', 30);
INSERT INTO users(id, email, age) VALUES (2, 'b@example.com', 40);
COMMIT;

SELECT email FROM users WHERE id = ?;

UPDATE users SET age = age + 1 WHERE email = ?;

DELETE FROM users WHERE id = ?;

SELECT id, email, age
FROM users
WHERE active = 1
ORDER BY age DESC
LIMIT 10;
```

Once that script works through parser → binder → planner → executor → kernel → recovery tests, Phase 5 has its foundation. Everything else becomes controlled expansion.
