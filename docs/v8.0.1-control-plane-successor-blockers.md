# v8.0.1 control-plane successor blockers

This clean `origin/main` successor prepares the authority manifest and the control-plane-owned
version/evidence paths for `8.0.1`. It deliberately does not copy the unreviewed release-runner
stack into this branch.

## External identity receipts

The reviewed release-runner successor must not require `jain-split-ops`, `jain`, or
`jain-deploy` to commit their own final commit SHA or a digest that includes that SHA. Such a
tracked self-identity is a fixed-point problem and cannot be made truthful by repeatedly editing
the repository.

That successor is blocked until the release-runner stack is reviewed and landed. Its acceptance
contract is:

- the authority declares that these three entries obtain identity from an external receipt,
  instead of carrying an in-tree `release_commit` or release checksum;
- the runner receives the receipt path explicitly from the release evidence root and rejects a
  receipt tracked by the repository whose identity it proves;
- each receipt binds the release version, repository, canonical remote, branch, exact 40-byte
  reviewed main commit SHA, immutable-tag intent, required check, and the reviewed lifecycle evidence;
- CI and tag operations consume that bound commit without rewriting the repository being proved;
- a missing, stale, malformed, mismatched, or self-tracked receipt is a hard block.

No external-identity schema or runner behavior is implemented here because clean `origin/main`
does not yet contain the release-candidate graph. Implementing a second graph in parallel would
create two release authorities.

## Fresh graph topology

The authority topology itself is ready for a fresh graph: Contracts follows Core, Agent/Jnoccio/
Research follow LLM, Report/TUI precede their CLI/Web consumers, and Core explicitly declares its
Battle GPU dependency. Structural validation now rejects negative, duplicate, unused, missing, or
out-of-order waves and simulates the all-`PENDING` graph to prove every node is reachable.

Historical `docs/release-evidence/8.0.0/` files remain immutable. New default receipts derive from
the active `8.0.1` release version. Candidate metadata remains fail-closed and the rollback target
remains `7.0.6`.

The authority deliberately declares Redline `identity_status = "pending"` without an immutable
tag. Release preflight, lock generation, and cutover fail closed until the exact reviewed successor
tag exists and a follow-up protected authority PR binds it. No `.jain.N` value is guessed.

The portal and deploy product repositories intentionally remain unchanged here. The exact
generated views are tracked first as `derived-manifests/{portal,deploy}.toml` in this repository,
so derived validation no longer requires a cross-repository write. Each reviewed artifact must
then be copied byte-for-byte through its own protected consumer PR. `bump-version` remains
authority-only and preserves each lawful `split.N` revision, including reruns.

The family `--check-paths` gate remains externally blocked by the missing Jain Python governance
files (`AGENTS.md`, `agent/owner-map.json`, and `agent/test-map.json`). The anchored Python boundary
also correctly reports `jain-core/jain-export/model.py` outside the declared boundary. This change
does not waive or conceal either separate repository repair.
